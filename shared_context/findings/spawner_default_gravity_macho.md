# Spawner 缺省重力（发售版 Mach-O / ARMv7）

## 结论

XML 未提供非空 `gravity` 时，Spawner 的构造缺省为 `(0, -1, 0)`。这是原版构造器写入的确定值，不是未初始化内存，也不是重建兼容策略。

## ARM 指令链

证据：`spawner_default_gravity_asm_macho.txt`，Ghidra 12.1.4 对发售版 `FruitNinjaPuss` 的完整反汇编。

1. `FUN_00053cb8` 在 `0x0005437a` 将元素大小设为 `0x90`，`0x00054382` 把分配大小设为 `count * 0x90 + 8`，`0x0005439e` 调用 `operator.new[]`。
2. `0x000543a2` 在分配地址 `+0` 写入 `0x90`，`0x000543a6` 在 `+4` 写入元素数。`0x0005443a` 将地址加 8，`0x0005443c` 把结果保存为 WaveInfo 的 Spawn 数组基址 `+0x48`。
3. 初始化循环以原始分配地址为基址：`0x000543e0` 向 `+0x28` 写 0，`0x000543e4` 向 `+0x2c` 写 `0xbf800000`（-1.0），`0x000543e6` 向 `+0x30` 写 0。
4. 减去 8 字节数组头后，上述写入对应 Spawner 的 `+0x20/+0x24/+0x28`。因此 gravity XYZ 缺省依次为 `0/-1/0`。
5. `0x0005444a` 读取同一数组基址，`0x00054452` 调用 `FUN_000537ec`。解析器只有在 XML 字符串存在且首字节非零时才进入覆盖分支（`0x00053aea` 至 `0x00053af2`）；`0x00053afc`、`0x00053b00`、`0x00053b04` 分别覆盖 Spawner `+0x20/+0x24/+0x28`。

## 重建约束

- `Spawner.gravity == nil` 表示 XML 未覆盖，运行时必须使用上述构造缺省。
- 显式 gravity 仍按 XML 的三个 Float 分量覆盖，不得与缺省值混合。
- `FUN_00057000` / `FUN_000568f4` 对 gravity 的后续变换保持原有实现，本证据只闭合缺省来源。
