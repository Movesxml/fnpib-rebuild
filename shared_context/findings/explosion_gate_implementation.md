# 爆炸切割门控：实现依据与边界

## 已核实行为

- `FUN_00020c38` 的正常炸弹命中路径先上报 `bomb`，再将全局单例 `+0x24` 写为 `3.2`，随后创建爆炸并播放 `Bomb-explode`。
- `FUN_00016214` 的水果、炸弹和特殊实体遍历只在 `+0x24 <= 0.0` 时进入；该条件不包住 combo 结算。
- `FUN_0001b384` 的反汇编在 `0001b5ce…0001b5d6` 对每个玩家调用 `vtable+0x14`。`FUN_0001f018` 先调用它，再在 `0001f0…` 的对应分支推进单例 `+0x24`，因此计时递减位于玩家实体主循环之后。
- 正计时分支按当前步长递减；当前重建尚未接入模式 1，所以没有加入该模式的第二次递减。
- 重建在跨越零点时钳为 `0`，与初始化/门控使用的非正状态一致；本批不实现尚未接入的阈值回调。

## 同帧顺序

1. 帧初使用已有计时决定是否遍历实体。
2. 炸弹命中时写 `3.2`，并结束本帧后续炸弹遍历。
3. 完成主循环后，从刚写入的计时中减去当前 `dt`。
4. 下一帧计时仍为正，因此不遍历；计时归零的那一帧仍沿用帧初的阻断结果，再下一帧恢复。

## 本批刻意不做

- 不把 3.2 秒计时简化为永久布尔锁。
- 不把 `FUN_00020d8c` 的 2.0 秒菜单炸弹分支混入普通炸弹命中。
- 不臆造 1.5 / 1.55 秒回调、模式 1 双速递减或时间缩放行为。
- 不把爆炸实体创建和视觉特效标记为已经完成。
