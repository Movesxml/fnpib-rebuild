# UIScreen 绘制属性：Mach-O 取证结论

范围：原始 ARMv7 `FruitNinjaPuss`，本记录只覆盖已闭合的普通纹理绘制属性。 nine-patch、字体和完整绘制顺序不在本记录内。

## 纹理坐标

- `FUN_003d6acc` 的非 nine-patch 分支使用 `texCoordPos` / `texCoordSize`。
- 四角 UV 为：左上 `pos`，右上 `pos + [size.x, 0]`，左下 `pos + [0, size.y]`，右下 `pos + size`。
- 缺省 `pos = [0,0]`、`size = [1,1]`。负 size 保留方向反转，不归一化、不取绝对值。

## 颜色存储与动画插值

- 属性访问器 `FUN_003d25f4` 将颜色以四个连续字节存于属性值 `+0x48...0x4b`，顺序为 R、G、B、A。
- 普通组件默认颜色来自 `PTR_DAT_004d9080` 指向的白色；`FUN_0031058c` 将运行时 `DAT_00603c68` 初始化为 `0xffffffff`，所以无父级时的父颜色也是 `[255,255,255,255]`。
- 颜色轨道更新 `FUN_003e64e8` 调用 `FUN_00310490` / `FUN_003104d8`。后者将前后关键帧的 RGBA 字节转换为 Float，按 `next - (next - previous) * (1 - amount)` 计算，再 `FPToFixed` 写回字节。对应汇编转换为向零截断。因而动画颜色在写回组件属性前已量化为字节，不能将浮点动画颜色保留到父子调制之后。
- 已导出的 Swift 轨道值与原始字节在合法 `0...255` 域内一致；投影时必须在活动 colour 采样后逐通道向零截断为字节。

## 父子调制

- `FUN_003d8dd0` 读取当前组件本地 RGBA（缓存位于 `+0x6b0...0x6b3`）及父级绝对颜色。
- 每通道计算顺序为 `Float(localByte) / 255.0`，再乘 `Float(parentByte)`，随后向零截断写回当前绝对颜色。`DAT_003d8ed8` 已读出为 `0x437f0000`，即 `255.0`。
- 不对结果额外 clamp 或 round；合法字节输入自然落在 `0...255`。
- 父级缺失时使用上述默认白色，因此根节点绝对颜色等于自身颜色。

## enabled 与绘制入口纠错

- 真正的 `enabled` 是基础组件 `+0x260` 指向属性值的 `+0x48` 字节；构造函数默认值为 true，UISF 静态值可以覆盖。
- `FUN_003dbd40` / `FUN_003dbd98` 读取的 `+0xa1c` 不是 enabled。`FUN_003db164` 注册 `DAT_00604b10`，静态初始化 `FUN_003dd424` 给出字符串 `drawninepatch`，默认值为 1。该分支不能用于 enabled。
- 输入／更新路径会检查自身及父级 enabled；显示遍历的完整 enabled 筛选位置尚未全部闭合。
- 当前几何／绘制属性投影只携带组件自身 enabled，不向子节点传播。根资源静态 enabled=false 不得被擅自用于隐藏整棵生产组件树。

## 独立屏幕可见性

- `+0x6ee` 是屏幕范围交叉可见标志，不是 enabled，也不是 drawNinePatch。
- `FUN_003d8d04` 由组件屏幕范围与视口计算该标志。`FUN_0038f2fc(x, 1.0)` 的实际语义是 `-x < 1.0`，即 `x > -1.0`。
- 因而通过尺寸检查后，可见条件为：宽、高分别 `> -1`，右边缘 `> 0`，左边缘 `< viewportWidth`，下边缘 `> 0`，上边缘 `< viewportHeight`。
- 该标志与 enabled 分开投影。逻辑投影使用逻辑视口；设备像素投影使用设备视口，不能混用 1 像素阈值。
