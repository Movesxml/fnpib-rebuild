## 2. C-01..C-03：Debug 版浮点常量的 double 池化（闭合）

**根因** [exe] `H`：Debug 构建（/Od）把浮点字面量按 **8 字节 double** 放进 `.rdata`；
上一轮以 f32 读 `0x16f2018` / `0x16f2028`，读到的是 double 的**低 4 字节**（尾数低位），
所以出现 `-1.08e-19` / `0.0` 这种"常数丢失"的假象。

**字节证据**（`t007_exe_neighborhood.md`，`0x16f2010` 起 48 字节，小端）：

| 地址 | 8 字节 | 作为 double | 语义 | 置信 |
|---|---|---|---|---|
| `0x16f2010` | `00 00 00 00 00 00 00 00` | 0.0 | 零填充/float 0.0 | M |
| `0x16f2018` | `00 00 00 a0 99 99 a9 3f` | **0x3FA99999A0000000 = 0.05000000074505806** | **double(0.05f) = 轨迹超时 0.05s** | H |
| `0x16f2020` | `00 00 00 00 00 00 00 00` | 0.0 | 零填充 | M |
| `0x16f2028` | `00 00 00 00 00 00 2e 40` | **0x402E000000000000 = 15.0** | **15.0 = 碰撞半径归一化除数** | H |
| `0x16f2030` | `00 00 00 00 00 00 00 00` | 0.0 | 零填充 | M |
| `0x16f2038` | `00 00 00 a0 99 99 c9 3f` | **0x3FC99999A0000000 = 0.20000000298023224** | **double(0.2f)，语义待定位**（C-05） | H(值)/L(语义) |

**关键判读（比"是 double"更强的结论）**：
`0x16f2018` 的值是 `double(0.05f)` = `0x3FA99999A0000000`，
**而不是** double 字面量 `0.05` 的 `0x3FA999999999999A`。
两者只差尾数第 8 位（`A0000000` vs `9999999A`），这恰好是 float→double 扩展的特征。
→ 说明源码写的是 `0.05f`（float 字面量），被编译器提升后以 double 形态池化；不是源码写了 double 0.05。
→ 对重建的意义：**用 `0.05f` 而非 `0.05`**，否则会引入 float/double 精度差，影响 `+0x17c > 0.05` 这类计时比较的边界行为。

**`0x16f2028` 交叉校验**：`t007_exe_f64.md` 报 `0x16f2028 (f64) = 0x402e000000000000 = 15.0`，
与邻域 dump 的 `00 00 00 00 00 00 2e 40` 完全一致 → 双向自证。

**结论**：exe 侧 15.0 / 0.05 / 0.5 三项**全部与 macho 一致**，上一轮"exe 读数异常"归零 [both] `H`。
T-006 记录的"exe 2 个 float 读数异常"由此结案，不再需要在重建时对 exe 值打折（数值层面）。

## 3. C-04 订正：`0x197f47c` 不是 double

`0x197f47c % 8 = 4` → **非 8 字节对齐**，不可能是一个 double 常量的起始。
`t007_exe_f64.md` 里那条 `0x197f47c (f64) = 0x0000000000000000` 属**非对齐伪读**（恰好近邻也是 0）。

正确判读：`0x197f47c` = **float 0.0**（4 字节），与 `FUN_00bda510` 中
`param_1 = _DAT_0197f47c;`（赋给 float 形参、在 `dt == 0` 分支被使用）一致 [exe] `H`。

**意义**：
1. 结论不变——dt 兜底槽静态初值 = 0.0；
2. 但**不能**把它并入"double 常量池"一族，否则会得出"兜底步长是 double"的错误推论；
3. 反向支持 T-006 结论 5（"固定步长"实为**上一帧 dt 缓存**）：静态初值 0.0，运行期由主循环写入，
   所以重建必须实现为"缓存上一帧 dt"，而不是硬编码某个固定步长。

## 5. C-06 / C-07：macho GOT 懒绑定（明确结论：运行时求值）

### 5.1 直接证据解码

`t007_macho_globals.md`：

- `ptr[0x4d90b4] = 0x00412604`，该处字节 `04 c0 9f e5 / 0c c0 8f e0 / 00 f0 9c e5 / e8 7b 0c 00`
  - `e59fc004` = `ldr r12, [pc, #4]`
  - `e08fc00c` = `add r12, pc, #12`
  - `e59cf000` = `ldr pc, [r12]`
  - `000c7be8` = 紧随其后的 GOT 槽偏移（未绑定时的 binder 入口）
  → 教科书式 ARM `__stubs` **懒绑定桩**（dyld 首次调用后回填真实地址）。

- `ptr[0x4d9048] = 0x00412454`，其后 **72 字节 = 6 个同构 12 字节桩**
  （`ldr r12,[pc,#4]` / `add r12,pc,#12` / `ldr pc,[r12]` / `0x000c7bxx` 级 GOT 偏移，循环重复）。
  → `0x4d9048` 在静态镜像里命中的是**桩表入口**，不是"Globals 单例结构体"。

### 5.2 结论（三条，可直接写进重建设计）

1. **`DAT_004d90b4`（特殊果加成量）静态不可解** [macho] `L`。
   重建时**不得**假设它是某个具体常量；`+0x110 += DAT_004d90b4`（core_logic_notes §1.2 步骤 4）
   需要设计成可配置项，真机 lldb/Frida 实测后再定值。
2. **`PTR_DAT_004d9048` 的字段偏移仍可用**，因为偏移来自反汇编的**直接寻址**（不依赖解引用）：
   - `PTR_DAT_004d9048[0x18]` → **+0x60**
   - `PTR_DAT_004d9048[10]` → **+0x28**
   （按 Ghidra 把基址视作 `int*` 索引推演；基类型待确认 [待验证]）
   语义：`FUN_00017d74` 前置门控 `两开关均为 0 才进入正常切割判定`
   → 疑似「暂停 / 调试 / 保护」双开关。重建时需要一个 `GlobalSwitches` 配置对象，含 0x28 与 0x60 两个 bool 位。
3. **dt 兜底槽 +0x44 同样运行时初始化**（关闭项与 C-04 自洽：静态初值 0）。
4. **不迁移**：现代 dyld（chained fixups）没有 lazy binding 机制，这一现象在新工程中不存在，
   反之也提醒——**不能拿现代裁剪/链接后的符号布局去套 2013 年的 Mach-O**。

## 7. C-09：`FUN_002ed344` 同体性 —— 输入错配，未闭合

### 7.1 事实

`deep_collide_2ed344.md` 的标题为 `FUN_0002ed344 — 002ee2a0`，但：
- **函数名 = `FUN_002ee2a0`**（不是 0x2ed344）
- 函数体 187 字节，调用者数 0，被调用者 7
- 内容为**渲染上下文初始化**：`glDepthMask(1)` / `glDepthFunc(0x203)` / `glClear(0x4500)` / `glViewport`

即导出器按符号名 `FUN_0002ed344` 解析时落到了相邻函数 `0x2ee2a0`。
（两地址相差 0x1A6C，同属一个编译单元的渲染模块。）

### 7.2 同体性判定：**不同体**

| 维度 | `ctx->vtable+0x0C`（切割相交，slash_geometry §5 契约） | `FUN_002ee2a0`（实际导出） |
|---|---|---|
| 参数 | `(self, other, out vec3)` 3 参 | `(this)` 1 参 |
| 返回 | `uint32`（布尔） | `void` |
| 函数体内容 | 浮点几何（`FloatVectorSub/Mult/Add`、`sqrtf`=`FUN_00301044`） | GL 状态机 + 视口查询（`vtable+0x9C`/`+0xA0`） |
| 副作用 | 输出点写入 | 清屏、设置深度态 |

→ **同体性问题无法回答**：被比对的不是目标函数。**需重导 0x2ed344**。

### 7.3 重导判据（给下一轮）

正确导出物应满足：函数体以 `FloatVectorSub/Mult/Add` 与 `FUN_00301044`（sqrtf）为主，
**不含** `_gl*` 调用；返回类型为整型；被 `FUN_00017d74` 或其实体更新链路调用。

### 7.4 附带收益（该误导出物的可用情报）

`FUN_002ee2a0` 虽非目标，但暴露了渲染上下文接口与 GL 状态设定，对 Metal 迁移有用：

- `_glDepthFunc(0x203)` = **`GL_LEQUAL`**
- `_glClear(0x4500)` = `0x4000 | 0x0400 | 0x0100` = **COLOR | STENCIL | DEPTH** ← 注意**含模板缓冲**
- `(**(code **)(*param_1 + 0x9c))(param_1)` / `+0xa0` → 返回**宽 / 高**（与 `DAT_0052be20` 表比对后可能交换，即横竖屏翻转）
- `DAT_00531000 = 3` → 某状态枚举值 3 [待验证]

## 8. C-11：exe 全局状态槽一次性闭合（附带产出）

从 `FUN_00bda510` 与 `t007_exe_neighborhood.md` 反查得到的**单例/全局**（与 GameState 结构体独立）：

| 地址 | 类型 | 语义 | 静态值 | 置信 |
|---|---|---|---|---|
| `0x019514b5` | byte | `dt==0` 时置 1 的标志 | — | H [exe] |
| `0x019514c0` | float | 归一化权重最大值累加器（↔ macho `0x5573b8`） | — | H [both] |
| `0x019514dc` | u32 | 门控位域；`&0x40` 禁用遍历、`&2`/`&1` 分支 | **0** | H [exe] |
| `0x0197f45c` | float | 冻结/爆炸计时（↔ macho `PTR+0x24`） | — | M [both] |
| `0x016ec7e0` | float | 零比较常量 `0.0f` | 0.0 | M [exe] |
| `0x0197f47c` | float | dt 兜底初值 | **0.0** | H [exe]（C-04） |

**双向印证**（写进重建规格）：
- exe：`_DAT_0197f45c != 0.0f` → **跳过**实体遍历
- macho：`PTR+0x24 <= 0.0` 且 `flags & 0x40 == 0` 且 单例 `vtable+0x28` 返回真 → **才进行**遍历
两者语义一致（计时器未归零则暂停切割判定），是 [`both`] `H` 级结构对齐。

`0x019514dc` 静态 = 0 说明所有门控位默认关闭 → 正常游玩路径不被 Debug 开关拦截，
重建时**不需要**保留这些位（它们是调试/开发用，按 `binary_equivalence.md` 风险 1 忽略）。
