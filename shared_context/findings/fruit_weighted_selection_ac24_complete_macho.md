## 2. 参数语义

### `param_1`：选择策略值，不是候选数量，也不是 `challengeFruitSize`

`param_1` 只在两条分支中分别与 0 或 1 比较。它决定使用哪一组权重和过滤条件，并且其作用还受 `P = FUN_0005809c(FUN_00052f80(), 0)` 影响。完整真值表见第 5 节。

已观察到的调用：

- 四个挑战水果包装函数 `FUN_0000af50`、`FUN_0000afc4`、`FUN_0000b06c`、`FUN_0000b1a4` 的调用点均传 0。
- `FUN_0000af04` 构造包含全部水果 ID 的数组，并把自身参数原样转发给 `FUN_0000ac24`；其它调用点可传 0 或 1。

因此不能把 `param_1` 简化成始终成立的“不过滤”或“只选特殊水果”；必须连同 `P` 一起实现。

### `param_2`：32 位水果 ID 数组指针

每个元素直接作为 FruitInfo 索引，并在命中时原样返回。函数不检查空指针，也不复制或排序数组。

### `param_3`：候选元素数量

- 重建和扫描循环使用有符号比较，只有 `param_3 > 0` 才进入。
- 末尾回退使用无符号 `param_3 >= 2` 判断是否缩放索引。
- 该混合符号语义会影响空候选和单候选边界，不能统一当成普通正整数处理。

## 3. FruitInfo 字段与四个全局权重和

设 `info = DAT_005d4cdc + id * 0x338`：

| 字段 | 本函数中的精确用途 |
|---|---|
| `info + 0x308` | 32 位基础权重；配置解析对应 `chance`。本函数只读取，从不改写。 |
| `info + 0x30c` | 按候选顺序累计的“全部候选”权重；仅在重建阶段写入。 |
| `info + 0x310` | 按候选顺序累计的“`+0x318 != 0` 候选”权重；仅在重建阶段写入。 |
| `info + 0x318` | 一个字节的运行时过滤谓词，本函数只判零/非零。配置管线涉及 `noCritical` 及其它覆盖条件，不能把该字节简单当成原始 XML 文本值。 |
| `info + 0x328` | 32 位过滤值；配置解析最终对应 `coinsMax`。本函数以有符号 `<= 0` 判定是否纳入两条过滤权重路径。 |

四个全局累计值：

| 地址 | 本文记号 | 含义 |
|---|---|---|
| `DAT_00556cc0` | `T_all` | 所有候选的 `+0x308` 之和。 |
| `DAT_00556cc4` | `T_free` | 仅 `+0x328 <= 0` 候选的权重和。 |
| `DAT_00556cc8` | `T_flag` | 仅 `+0x318 != 0` 候选的权重和，不检查 `+0x328`。 |
| `DAT_00556ccc` | `T_flagFree` | 同时满足 `+0x318 != 0`、`+0x328 <= 0` 的权重和。 |

这些名称只是按指令条件命名的语义记号，不是反编译器提供的原始符号。

## 4. 权重与累计值的重建顺序

入口先以有符号方式检查 `T_all`：

```text
if int32(T_all) <= 0:
    T_all = 0
    if int32(param_3) > 0:
        按 param_2 原顺序逐项处理
```

逐项顺序不可交换：

1. 读取 `w = info[+0x308]`。
2. `T_all += w`，并立即把新值写入 `info[+0x30c]`。
3. 若 `info[+0x328] <= 0`，执行 `T_free += w`。
4. 若 `info[+0x318] != 0`：
   - 执行 `T_flag += w`；
   - 若同时 `info[+0x328] <= 0`，执行 `T_flagFree += w`。
5. 把当前 `T_flag` 写入 `info[+0x310]`。即使当前项 `+0x318 == 0`，也会写入此前已经累计的 `T_flag`。

所有加法和存储都是 32 位 ARM 运算；若研究溢出，应按 32 位位模式回绕，后续比较再按指令要求解释为有符号或无符号。

### 缓存边界

- 若入口 `int32(T_all) > 0`，本函数完全跳过重建；即使 `param_2` 已换成另一组候选，也继续复用旧全局和及 FruitInfo 中旧的 `+0x30c/+0x310`。
- 重建时只显式清零 `T_all`，**没有清零 `T_free`、`T_flag`、`T_flagFree`**。后三者会在旧值上继续累加。
- `+0x308`、`+0x318`、`+0x328` 均不被本函数修改；更新的是全局和与 `+0x30c/+0x310` 累计字段。

这部分状态性是编写独立 Swift 测试时必须显式初始化的前置条件。

## 5. 四条加权选择路径

完成可能的重建后：

1. `0x0000acd4` 调 `FUN_00052f80`，再以参数 0 调 `FUN_0005809c`，得到谓词 `P`。
2. `0x0000ace0` 再次调 `FUN_00052f80` 取得同一个全局对象。
3. 在四条路径之一内联推进一次 64 位 LCG，并得到新状态高 32 位 `H`。
4. 根据该路径的总量 `N` 计算 `roll`，再按原候选顺序扫描。

| 条件 | 总量 `N` | 扫描方式 |
|---|---|---|
| `P == 1 && param_1 == 1` | `T_flag` | 不再次过滤；直接读取每项预先写入的 `info[+0x310]`。 |
| `P == 1 && param_1 != 1` | `T_flagFree` | 只累计并检查 `+0x328 <= 0 && +0x318 != 0` 的项；局部累计从 0 开始。 |
| `P != 1 && param_1 == 0` | `T_free` | 只累计并检查 `+0x328 <= 0` 的项；局部累计从 0 开始。 |
| `P != 1 && param_1 != 0` | `T_all` | 不再次过滤；直接读取每项预先写入的 `info[+0x30c]`。 |

四个挑战包装函数传 `param_1 == 0`，所以它们只会走第二行或第三行，不会走两条“忽略过滤条件”的路径。

## 6. PRNG、roll 计算与比较边界

### 6.1 实际 PRNG

`FUN_00052f80` 返回全局对象 `0x005a7b80`，本身不推进随机状态。四条加权路径及末尾回退都内联同一个 64 位 LCG：

```text
state  = (uint64(object[+0xc]) << 32) | object[+0x8]
mult   = (uint64(object[+0x14]) << 32) | object[+0x10]
inc    = (uint64(object[+0x1c]) << 32) | object[+0x18]
state' = state * mult + inc       // mod 2^64
写回 object[+0x8/+0xc]
H      = high32(state')
```

`FUN_0005809c` 只是返回控制分支的 0/1 谓词，不是另一个 PRNG。

- 每次进入 `FUN_0000ac24`，都会在四条加权路径之一推进一次该 LCG。
- 只有加权扫描没有返回时，`0x0000aeba` 才再次取得全局对象并第二次推进同一 LCG，用于末尾回退。
- 加权扫描命中时不会执行第二次推进。

### 6.2 加权 roll

令 `mulHi32(a, b) = high32(uint64(uint32(a)) * uint64(uint32(b)))`：

```text
若 uint32(N) == 0 或 uint32(N) == 0xffffffff：
    roll = H                         // 不做缩放
否则：
    roll = mulHi32(H, N)
```

对正常正权重总量 `N > 0`，这等价于 `floor(H * N / 2^32)`，范围为 `0 .. N-1`。

### 6.3 扫描比较

四条路径均使用**有符号严格小于**：

```text
if int32(roll) < int32(cumulativeWeight):
    return 当前候选 ID
```

因此：

- `roll == cumulativeWeight` 时不选当前项，继续下一项。
- 对单调非负累计权重，`roll == previousCumulative` 是下一项的起点。
- 对正常正总量，最后一项在 `roll == N-1` 时命中。
- 零权重项在正常非负 roll 下没有可选区间，因为累计值不增加且比较不是 `<=`。

关键指令包括 `0x0000ad54..0x0000ad56`、`0x0000adc0..0x0000adc2`、`0x0000ae38..0x0000ae3a`、`0x0000aeb0..0x0000aeb2`。

## 7. 末尾候选数组回退

加权扫描未命中后，函数第二次推进 LCG，得到新的 `H2`，然后：

```text
if uint32(param_3) >= 2:
    index = mulHi32(H2, uint32(param_3 - 1))
else:
    index = H2                       // 不缩放
return param_2[index]
```

对应 `0x0000aeba..0x0000aef6`。

对 `param_3 >= 2`：

- 缩放因子使用的是 `param_3 - 1`，不是 `param_3`。
- `index` 范围是 `0 .. param_3-2`，所以**最后一个候选永远不会由该回退选中**。
- 两项时 `param_3 - 1 == 1`，`mulHi32(H2, 1) == 0`，回退始终返回第一项。
- 回退读取的是候选 ID，不再检查 `+0x308/+0x318/+0x328`。

## 8. 空候选、零权重和负权重

这些边界没有额外安全封装，不能描述成固定的“返回第一个”或“返回 -1”。

### 空候选 `param_3 == 0`

- 重建和加权扫描均不处理元素，但加权路径仍推进一次 LCG。
- 回退再推进一次 LCG。
- 因无符号 `param_3 < 2`，回退不缩放，直接执行 `param_2[H2]`。
- 这通常越界；即使 `H2 == 0` 偶然读到内存，也仍不是合法候选。**原函数没有定义良好的空候选返回值，也没有 -1 哨兵。**

### 单候选 `param_3 == 1`

- 若加权扫描命中，可正常返回该候选。
- 若进入回退，同样不缩放，执行 `param_2[H2]`；只有 `H2 == 0` 时才恰好指向唯一元素，其它情况通常越界。
- 所以不能给“单候选必返回唯一元素”写通用测试结论。

### 全部适用权重为零

在干净状态下，`N == 0` 使 `roll = H`，不再缩放：

- 若 `int32(H) >= 0` 且累计值均为 0，严格 `<` 不会命中，进入末尾回退。
- 若 `int32(H) < 0`，第一个被该路径扫描且累计值为 0 的项反而满足 `roll < 0`，会直接返回，即使其权重为零。
- 若 `T_all` 仍不为正，下次调用还会再次进入重建；其它三个全局和不在重建入口清零，测试不能假定每次都有干净缓存。

### 负权重或负总量

- 没有拒绝、钳制或绝对值处理；负权重直接参与 32 位累加。
- 累计序列可以下降，扫描仍只执行第一个 `int32(roll) < int32(cumulative)`。
- 总量 `N == -1` 时与 0 一样不做缩放；其它负值会作为巨大的 `uint32` 参与 `mulHi32`。
- 结果依赖具体权重序列、PRNG 高位和缓存状态，可能提前返回，也可能进入回退；不存在统一的“负权重返回某固定项”规则。

## 9. `[[controller + 0x64] + 0x4c]` 的原始配置字段

### 结论

该值对应当前挑战定义节点的 **`challengeFruitSize`**，不是 `originalModeInfo`，也不是 `challengeTier` 或 tier 序号。

`FUN_00062698(definition, challengeXML)` 的直接解析逻辑：

| XML 情况 | 写入 `definition + 0x4c` |
|---|---:|
| 缺少 `challengeFruitSize` | 0 |
| `challengeFruitSize == "small"` | 1 |
| `challengeFruitSize == "medium"` | 2 |
| `challengeFruitSize == "big"` | 3 |

关键指令：`0x0006271a..0x00062776`。字符串地址 `0x0041c183` 为 `challengeFruitSize`，后续依次为 `small`、`medium`、`big`，原始字节已单独导出。

未知非空字符串走 `0x0006277a`，不写 `+0x4c`；构造函数 `FUN_00062618` 也没有初始化该字段。因此不能把未知字符串当作 0 的测试向量。

### 对象与配置传递链

1. `FUN_00060878` 读取 `xml/ch1challengeList.xml`，遍历 `partyChallenges/challengeTier/challengeGroup`。
2. `FUN_0006f178` 遍历组内 `challenge` 节点，为每个节点分配 `0x104` 字节定义对象，调用 `FUN_00062618` 初始化，再于 `0x0006f22a` 调 `FUN_00062698(definition, challengeXML)`。
3. `FUN_0006ed60` 返回当前定义对象：若 tier 的 `+0xb0` 非零则返回它，否则返回 `tier[+0x78] + tier[+0x90] * 8` 中保存的定义指针。
4. 控制器当前定义位于 `controller + 0x64`；`FUN_00061128` 在 `0x00061178..0x0006117a` 读取其 `+0x4c` 并分派候选集合。

`challengeTier` 是外层分组节点，不是这个字段。组索引在 `FUN_0006f178` 中写向定义对象 `+0x54`，与 `+0x4c` 不同。`FUN_0006fa3c` 对 `xml/originalModeInfo.xml` 的解析只涉及 `magicBean` 的间隔/分数和 `timing` 的时间字段，没有这条挑战定义赋值链。

最终对应关系：

| `challengeFruitSize` | 运行时值 | `FUN_00061128` 候选集合 |
|---|---:|---|
| 缺失 | 0 | 没有模式 1/2/3 的专门覆盖；保留此前结果。 |
| `small` | 1 | `strawberry`、`kiwifruit`、`lime`。 |
| `medium` | 2 | `orange`、`mango`、`apple_red`、`tomato`、`apple`、`plum`、`passionfruit`、`lemon`、`peach`、`pear`。 |
| `big` | 3 | `banana`、`watermelon`、`pineapple`。 |

在 `FUN_00061128(param_2 == 0)` 的常见路径中，值 0 会保留默认初选“除 banana 外的全部 ID”；这属于调用上下文，不是 `FUN_00062698` 额外定义的候选集合。

## 10. 足以直接写成 Swift 测试向量的事实

### 10.1 分支与字段向量

可以固定 `P`、`param_1`、候选 ID、`chance`、`coinsMax` 和 `+0x318` 字节，逐项断言：

- 第 5 节四条路径选择的全局总量和过滤条件。
- `+0x30c` 是全部候选累计，`+0x310` 是 `+0x318 != 0` 候选累计，包括未标记项也写入当前累计值。
- `T_all > 0` 时不重建；`T_all <= 0` 时仅 `T_all` 被显式清零。
- `challengeFruitSize` 的缺失 / small / medium / big 映射，以及值 1/2/3 对应的挑战候选集合。

### 10.2 roll 与扫描边界向量

以下向量不需要知道真实 PRNG 种子，只需把新状态高 32 位 `H` 或 `roll` 注入纯算法：

| 向量 | 预期 |
|---|---|
| `H = 0xffffffff, N = 10` | `roll = mulHi32(H, N) = 9`。 |
| `H = 0x40000000, N = 10` | `roll = 2`。 |
| 权重 `[3, 7]`，`roll = 2` | 累计 `[3, 10]`，返回第一项。 |
| 权重 `[3, 7]`，`roll = 3` | 第一项因 `3 < 3` 为假而跳过，返回第二项。 |
| 权重 `[0, 5]`，`N = 5, roll = 0` | 第一项累计仍为 0，不命中；返回第二项。 |
| 干净零权重状态，`N = 0, H = 0` | 加权扫描不命中，进入回退。 |
| 干净零权重状态，`N = 0, H = 0xffffffff` | 有符号 `roll == -1`，首个被扫描的零累计项命中。 |
| 权重 `[-1, 2]`，`N = 1, H 任意` | `roll = 0`；累计 `-1` 不命中，累计 `1` 命中第二项。 |

### 10.3 回退向量

| 向量 | 预期 |
|---|---|
| 两项，任意 `H2` | `index = mulHi32(H2, 1) = 0`，返回第一项。 |
| 三项，`H2 = 0xffffffff` | `index = mulHi32(H2, 2) = 1`，返回第二项。 |
| 三项或更多项 | 回退索引最大为 `count - 2`，最后一项不可达。 |
| 加权扫描命中 | 只推进一次 LCG。 |
| 加权扫描未命中且 `count >= 2` | 推进两次 LCG，第二次结果用于回退。 |

### 10.4 不应写成正常返回值的向量

空候选和“进入回退的单候选”会产生未缩放索引及潜在越界，没有稳定的合法水果 ID 可供断言。安全 Swift 重写可以为这些输入定义显式前置条件或错误，但那是新增安全策略，不能冒充原函数返回语义。

若要从指定种子做完整端到端测试，还必须固定 PRNG 的 64 位初态、乘数、增量、四个全局和及谓词 `P`。若只测试选择和回退逻辑，注入 `H/H2` 已足够，且能避免把运行环境状态误写成常量。

### 10.5 Swift 实现时的位级注意事项

- 权重累加使用 32 位回绕语义，应使用 `UInt32` 位模式及 `&+`，不要依赖 Swift 默认的有符号溢出陷阱。
- 比较前显式执行 `Int32(bitPattern:)`，保留有符号严格 `<`。
- `mulHi32` 用 `UInt64` 乘积的高 32 位实现。
- 回退的 `count >= 2` 按无符号位模式判断，不能用普通 `Int` 条件笼统替代全部边界。
