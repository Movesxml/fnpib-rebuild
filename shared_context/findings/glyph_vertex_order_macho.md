## 0. 结论（可直接实现）

设一个字形记录 `g` 的字段：`w=g+0x38, h=g+0x3c, a=g+0x28, b=g+0x2c, u0=g+0x18, v0=g+0x1c, u1=g+0x20, v1=g+0x24, pen=(g+0x30,g+0x34), θ=g+0x40`。

~~~c
A = w - a;  B = h - b;  s = sin(θ);  c = cos(θ);
R(p,q) = (p*c - q*s, p*s + q*c);            // 0x31af76..0x31afe2 实证

c0 = pen + R( A, -b);   // 角#0  (w-a, -b)
c1 = pen + R(-a,  B);   // 角#1  (-a,  h-b)
c2 = pen + R(-a, -b);   // 角#2  (-a,  -b)
c3 = pen + R( A,  B);   // 角#3  (w-a, h-b)

// 6 个顶点 = 2 个独立三角形，共享对角线 c0–c1
if (renderer[0x1b4] == 1)
    v = { (c0,u1,v1), (c1,u0,v0), (c2,u0,v1), (c3,u1,v0), (c1,u0,v0), (c0,u1,v1) };
else
    v = { (c0,u1,v1), (c2,u0,v1), (c1,u0,v0), (c3,u1,v0), (c0,u1,v1), (c1,u0,v0) };

buf + drawnIndex*6*0x30   写 6 个顶点，每顶点 0x30 字节
~~~

**两支路只交换「第 2、3 个顶点」和「第 5、6 个顶点」**，即两个三角形各自反转一次；位置和 UV 都不变，只有绕序相反。
**UV 严格跟着角走**（每个角的 UV 在两支路里完全相同），不存在 UV 与位置错配。

**自校验**：把四组结果代回 `x' = p·c − q·s`、`y' = p·s + q·c`，四角全部吻合（这就是判定位序的依据）：

- c0：(p,q)=(A,−b) → x = A·c + b·s ✅(d10)  y = A·s − b·c ✅(d15)
- c1：(p,q)=(−a,B) → x = −a·c − B·s ✅(d14)  y = −a·s + B·c ✅(d9)
- c2：(p,q)=(−a,−b) → x = −a·c + b·s ✅(d11)  y = −a·s − b·c ✅(d8)
- c3：(p,q)=(A,B) → x = A·c − B·s ✅(d12)  y = A·s + B·c ✅(d17)

**lane 说明（不是歧义）**：只有 .lo 有意义。s17/s19/s21/s23/s25/s29/s31 全程无任何载入，是残留值；
12 个 `vstr.32` 写点全部只取 .lo（唯一例外 L131 的 `vstr.64` 连 d17.hi 一起写栈，但 L189 取回后也只用 s4 = .lo）。
所以 64 位 VFP 指令只是编译器打包，不影响结果。

| 角号（题面序） | 偏移 (p,q) | x 所在 | y 所在 | 写点 |

## 5. 六个顶点属于哪两个三角形 / 绕序

**分组固定为 (0,1,2) 与 (3,4,5)**（不是 0-1-2-3 条带，无索引缓冲），共享边是 **c0–c1**
（对角线从 (w−a,−b) 到 (−a,h−b)）：

| 支路 | 三角 A = (v0,v1,v2) | 三角 B = (v3,v4,v5) | 有向面积×2（θ=0 单位方格） |
|---|---|---|---|
| `==1` | (c0, c1, c2) | (c3, c1, c0) | 两个都 **+1** |
| `!=1` | (c0, c2, c1) | (c3, c0, c1) | 两个都 **−1** |

- 同一支路内两个三角形**同向**；两支路**严格相反**（每个三角形只是交换了第 2、3 个顶点）。
- 共享边 c0→c1 在三角 A 里正向、在三角 B 里反向 —— 两支路都满足「合法四边形」性质。
- 取 θ=0、pen=(0,0)、w=h=1、a=b=0：c0=(1,0) c1=(0,1) c2=(0,0) c3=(1,1)，代入
  `(x1−x0)(y2−y0) − (x2−x0)(y1−y0)` 即得上表正负号。
- 在「pen 的 +y 向下」的坐标系里：`==1` 两支路都是**屏幕顺时针**，`!=1` 都是**屏幕逆时针**。

## 6. 顶点 0x30 布局与收尾（两支路之后统一执行）

L213–L251 的 6 次循环（`r1` 步长 0x30、终止 0x120）：

| 偏移 | 值 | 行 |
|---|---|---|
| +0x00 / +0x04 | x / y（float） | 各支路 |
| +0x08 / +0x0c / +0x10 | 0（r8） | L241 / L243 / L245 |
| +0x14 | 1.0f（r3 = 0x3f800000） | L248 |
| +0x18 | byte2 | L237（`vstr s4`） |
| +0x1c | byte1 | L235（`vstr s6`） |
| +0x20 | byte0 | L233（`vstr s2`） |
| +0x24 | byte3（A） | L239（`vstr s0`） |
| +0x28 / +0x2c | u / v | 各支路 |

颜色取 `r6 = [elem+0x3c]` 的打包值；若 `[elem+4] != 0` 则用 `FUN_0031beb0` 从字形 +0x44 重算，
并把 `[elem+0x40]` 当 alpha 写回（L90–L104）。顶点数 `[elem+0xc] = n*6`（L48），
缓冲 `n*6*0x30` 字节（L47、L55）。`drawnIndex` 只在真正落笔的字形上自增（L257），跳过的字形不占位。

## 7. 歧义 / 未闭合

1. **`+0x1b4` 哪一支算「正面」——未定。** 本函数只证明两支路绕序相反、且各自内部一致。
   该全局在 `build_logs/app_seed_1b4_writers.md` 里只有 3 个写点（其中一处是 8 字节写 `[+0x1b4]`）、
   311 个读点，没有一处能定出文字路径的语义（t087 §8.4 亦列为未闭合）。缺：`FUN_0031fa44()` 返回对象里 +0x1b4 的初始化来源。
2. **屏幕绕序的绝对值依赖提交侧的 y 翻转。** `FUN_0031a7c8` 把 y 取负后再拷进组件 +0x784；
   若最终投影也是 y 向下，§5 的「顺/逆时针」整体反转。**相对关系（两支路相反）是确定的。**
3. **顶点 +0x18..+0x24 的 R/G/B 命名未定。** 只能给出「byte2/byte1/byte0/byte3 → +0x18/+0x1c/+0x20/+0x24」，
   要定 R/G/B 需 `FUN_0031beb0` / `FUN_0031048c` 的打包约定（未导出）。
4. **不是歧义、但易读错**：L87/L88 与 L153/L154 的 u1/v1 交叉重载（见 §1 注）；
   `s18` 先存 θ 后被 b 覆盖（θ 已由 L105 的 `vmov r5,s18` 取走，L109 才覆盖）。
