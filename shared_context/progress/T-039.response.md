## 设计说明

本卡只产出**值语义草案**（staging），不动生产文件。核心是把 `FUN_0000ac24` 拆成可显式注入的纯逻辑：

- **状态**：`ChallengeFruitWeightState` 显式持有四个全局和（`T_all/T_free/T_flag/T_flagFree`）+ 两个缓存字典（模拟 `+0x30c/+0x310` 写回 FruitInfo 的槽位，键为 `typeID`）。重建入口严格复刻：`int32(T_all) <= 0` 才重建、**只清零 `T_all`**、四项按原顺序回绕累加、每项都写 `+0x310`。
- **四路径**：`resolvePath(predicateP:param1:)` 用 `P == 1` / `param1 == 1/0` 原样分派；`scanWeighted` 对 `.flag/.all` 直读缓存、对 `.flagFree/.free` 局部累加并做 `coinsMax <= 0` / `noCritical` 过滤；比较统一 `Int32(bitPattern:)` 严格 `<`。
- **PRNG**：`OriginalLCGRandom.nextInt(0)`（`upperBound <= 0` 分支）恰好是"推进一次并返回新状态高 32 位"，加权路径一次、回退再一次；`mulHi32`/`roll`/`fallbackIndex(count-1)` 独立成数学函数便于注入向量。
- **候选集合**：`ChallengeFruitCandidates` 按 `FruitInfo.name` 动态匹配、按 catalog 原顺序输出 `typeID`；`unspecified` 返回 `nil`（原版无 1/2/3 覆盖）。`selectNewGameChallengeFruit` 复刻 `FUN_00061128` 的"先默认初选、模式 1/2/3 再覆盖"两次选择与共享缓存行为。
- **安全策略**：空候选、单候选进入回退在原版是 `param_2[H2]` 越界；Swift 在**完成同样两次 PRNG 推进后**抛明确错误，不伪造合法返回。

public enum ChallengeFruitSelectionError: Error, Equatable, Sendable {

    /// 候选 ID 在权重表中缺失。
    /// 原版候选 ID 一定是合法 FruitInfo 索引；这是 Swift 显式输入模型的前提校验，
    /// 不是原版返回值，也不得用猜测默认值填补。
    case missingWeightEntry(fruitID: Int32)

    /// 候选数超过 Int32 表示范围（原版 param_3 为 32 位）。
    case candidateCountOverflow(Int)

    /// **新增安全策略**：原版 `param_3 == 0` 时仍会推进两次 LCG，然后执行
    /// `param_2[H2]` 越界读取；没有定义良好的返回值，也没有 -1 哨兵。
    /// Swift 在完成同样的两次推进后抛出本错误。
    case emptyCandidates

    /// **新增安全策略**：`param_3 < 2` 时原版回退分支不做缩放，直接 `param_2[H2]`，
    /// 通常越界；单候选仅在 `H2 == 0` 时偶然合法。Swift 一律拒绝，不伪造该偶然返回。
    /// - Parameters:
    ///   - count: 原版 `param_3`
    ///   - unscaledIndex: 原版 `H2`（未缩放）
    case unsafeFallback(count: Int32, unscaledIndex: UInt32)

    /// 兜底：理论上 `param_3 >= 2` 时 `mulHi32(H2, param_3 - 1)` 落在 `0..param_3-2`，
    /// 不会越界；若调用方候选数组长度与 `param_3` 不一致则可能触发。
    case fallbackIndexOutOfBounds(count: Int32, index: UInt32)
}

// MARK: - 数学（可独立注入测试向量）

public enum ChallengeFruitSelectionMath {

    /// `high32(uint64(uint32(a)) * uint64(uint32(b)))`
    @inline(__always)
    public static func mulHi32(_ a: UInt32, _ b: UInt32) -> UInt32 {
        UInt32(truncatingIfNeeded: (UInt64(a) * UInt64(b)) >> 32)
    }

    /// 加权 roll（fruit_weighted... §6.2）。
    ///
    /// `UInt32(N) == 0` 或 `== 0xffffffff` 时不缩放，直接使用 `H`。
    @inline(__always)
    public static func roll(high: UInt32, total: UInt32) -> UInt32 {
        if total == 0 || total == UInt32.max {
            return high
        }
        return mulHi32(high, total)
    }

    /// 有符号**严格小于**：`int32(lhs) < int32(rhs)`。
    @inline(__always)
    public static func isSignedStrictlyLess(_ lhs: UInt32, _ rhs: UInt32) -> Bool {
        Int32(bitPattern: lhs) < Int32(bitPattern: rhs)
    }

    /// 末尾回退索引（fruit_weighted... §7）。
    ///
    /// - `uint32(count) >= 2`：`mulHi32(high, uint32(count - 1))`
    /// - 否则**不缩放**，返回 `high`（原版随之执行 `param_2[high]`，越界风险由调用方处理）
    @inline(__always)
    public static func fallbackIndex(high: UInt32, count: Int32) -> UInt32 {
        let unsignedCount = UInt32(bitPattern: count)
        guard unsignedCount >= 2 else { return high }
        return mulHi32(high, unsignedCount &- 1)
    }
}

// MARK: - 选择器

/// `FUN_0000ac24` 的值语义等价实现。
///
/// 状态在多次调用间保留，这是复刻原版全局缓存语义的必要条件：
/// 第二次传入不同候选数组时，只要 `int32(T_all) > 0`，原版就完全跳过重建并
/// 复用旧全局和与旧 `+0x30c/+0x310`（fruit_weighted... §4「缓存边界」）。
public struct ChallengeFruitSelector: Sendable {

    public private(set) var state: ChallengeFruitWeightState

    public init(state: ChallengeFruitWeightState = ChallengeFruitWeightState()) {
        self.state = state
    }

    // MARK: 路径分派

    /// 原版真值表（fruit_weighted... §5）：只有 `P == 1` 视为真；
    /// `param_1` 只与 0 / 1 比较，其它值落入 `!=` 分支。
    public static func resolvePath(predicateP: Int32,
                                   param1: Int32) -> ChallengeFruitWeightPath {
        if predicateP == 1 {
            return param1 == 1 ? .flag : .flagFree
        }
        return param1 == 0 ? .free : .all
    }

    private func totalWeight(for path: ChallengeFruitWeightPath) -> UInt32 {
        switch path {
        case .flag: return state.totalFlag
        case .flagFree: return state.totalFlagFree
        case .free: return state.totalFree
        case .all: return state.totalAll
        }
    }

    // MARK: 重建（§4）

    /// 按原版顺序重建权重缓存。
    ///
    /// 入口：`if int32(T_all) <= 0 { T_all = 0; if int32(param_3) > 0 { ... } }`
    ///
    /// 逐项顺序（不可交换）：
    /// 1. `w = info[+0x308]`
    /// 2. `T_all += w`，立即写 `info[+0x30c] = T_all`
    /// 3. `info[+0x328] <= 0` → `T_free += w`
    /// 4. `info[+0x318] != 0` → `T_flag += w`；同时 `+0x328 <= 0` → `T_flagFree += w`
    /// 5. 写 `info[+0x310] = T_flag`（**即使当前项 `+0x318 == 0` 也写此前累计值**）
    ///
    /// 注意：
    /// - 只显式清零 `T_all`；`T_free/T_flag/T_flagFree` 在旧值上继续累加。
    /// - 全部加法为 32 位回绕（`&+`），比较时按位模式解释符号。
    /// - 中途抛 `missingWeightEntry` 时状态已部分写入，与原版部分写回一致。
    public static func rebuildIfNeeded(state: inout ChallengeFruitWeightState,
                                       candidates: [Int32],
                                       weights: [Int32: ChallengeFruitWeightEntry]) throws {
        guard Int32(bitPattern: state.totalAll) <= 0 else { return }

        state.totalAll = 0

        // param_3 是有符号比较，只有 > 0 才进入循环。
        guard !candidates.isEmpty else { return }

        for fruitID in candidates {
            guard let entry = weights[fruitID] else {
                throw ChallengeFruitSelectionError.missingWeightEntry(fruitID: fruitID)
            }

            let w = UInt32(bitPattern: entry.chance)

            state.totalAll = state.totalAll &+ w
            state.cumulativeAll[fruitID] = state.totalAll

            let coinsMaxNonPositive = entry.coinsMax <= 0
            if coinsMaxNonPositive {
                state.totalFree = state.totalFree &+ w
            }

            if entry.noCritical { // +0x318 != 0
                state.totalFlag = state.totalFlag &+ w
                if coinsMaxNonPositive {
                    state.totalFlagFree = state.totalFlagFree &+ w
                }
            }

            // 每项都写；非 noCritical 项写入的是此前累计的 T_flag。
            state.cumulativeFlag[fruitID] = state.totalFlag
        }
    }

    // MARK: 扫描（§6.3）

    /// 按路径扫描累计权重；命中返回候选 ID，未命中返回 `nil`。
    ///
    /// 四条路径一律使用**有符号严格小于**：
    /// `Int32(bitPattern: roll) < Int32(bitPattern: cumulative)`。
    ///
    /// - `.flag` / `.all`：直接读取重建阶段写入的缓存槽，**不再累加、不再过滤**。
    ///   缓存槽缺失按 0 处理：原版 FruitInfo 构造即把 `+0x30c/+0x310` 置 0
    ///   （fruit_info_defaults... §2.1，`FUN_00015404`），不是猜测缺省值。
    /// - `.flagFree`：局部累计从 0 开始，只处理 `coinsMax <= 0 && noCritical`。
    /// - `.free`：局部累计从 0 开始，只处理 `coinsMax <= 0`。
    public static func scanWeighted(path: ChallengeFruitWeightPath,
                                    roll: UInt32,
                                    candidates: [Int32],
                                    weights: [Int32: ChallengeFruitWeightEntry],
                                    state: ChallengeFruitWeightState) throws -> Int32? {
        switch path {
        case .flag:
            for fruitID in candidates {
                let cumulative = state.cumulativeFlag[fruitID] ?? 0
                if ChallengeFruitSelectionMath.isSignedStrictlyLess(roll, cumulative) {
                    return fruitID
                }
            }

        case .all:
            for fruitID in candidates {
                let cumulative = state.cumulativeAll[fruitID] ?? 0
                if ChallengeFruitSelectionMath.isSignedStrictlyLess(roll, cumulative) {
                    return fruitID
                }
            }

        case .flagFree:
            var local: UInt32 = 0
            for fruitID in candidates {
                guard let entry = weights[fruitID] else {
                    throw ChallengeFruitSelectionError.missingWeightEntry(fruitID: fruitID)
                }
                guard entry.coinsMax <= 0, entry.noCritical else { continue }
                local = local &+ UInt32(bitPattern: entry.chance)
                if ChallengeFruitSelectionMath.isSignedStrictlyLess(roll, local) {
                    return fruitID
                }
            }

        case .free:
            var local: UInt32 = 0
            for fruitID in candidates {
                guard let entry = weights[fruitID] else {
                    throw ChallengeFruitSelectionError.missingWeightEntry(fruitID: fruitID)
                }
                guard entry.coinsMax <= 0 else { continue }
                local = local &+ UInt32(bitPattern: entry.chance)
                if ChallengeFruitSelectionMath.isSignedStrictlyLess(roll, local) {
                    return fruitID
                }
            }
        }

        return nil
    }

    // MARK: 主选择（FUN_0000ac24）

    /// 值语义等价选择。
    ///
    /// PRNG 次数：
    /// - 加权扫描命中：恰好推进一次。
    /// - 未命中：再推进一次用于末尾回退（共两次）。
    /// - 空候选 / 单候选进入回退时同样先完成两次推进，然后抛安全错误。
    ///
    /// - Parameters:
    ///   - candidates: 原版 `param_2`（32 位水果 ID 数组）；长度即 `param_3`。
    ///   - weights:    显式权重条目（键 = FruitInfo `typeID`）。
    ///   - param1:     原版 `param_1`（挑战包装函数传 0）。
    ///   - predicateP: 原版 `P == 1` 才视为真；调用方负责求值。
    ///   - random:     真实 `OriginalLCGRandom`（见 `nextHighBits` 说明）。
    public mutating func select(candidates: [Int32],
                                weights: [Int32: ChallengeFruitWeightEntry],
                                param1: Int32,
                                predicateP: Int32,
                                random: RandomSource) throws -> Int32 {
        guard candidates.count <= Int(Int32.max) else {
            throw ChallengeFruitSelectionError.candidateCountOverflow(candidates.count)
        }
        let param3 = Int32(candidates.count)

        try Self.rebuildIfNeeded(state: &state, candidates: candidates, weights: weights)

        let path = Self.resolvePath(predicateP: predicateP, param1: param1)
        let total = totalWeight(for: path)

        // 四条加权路径之一，内联推进一次 LCG。
        let high = Self.nextHighBits(random)
        let rollValue = ChallengeFruitSelectionMath.roll(high: high, total: total)

        if let hit = try Self.scanWeighted(path: path,
                                           roll: rollValue,
                                           candidates: candidates,
                                           weights: weights,
                                           state: state) {
            return hit
        }

        // 末尾回退：第二次推进同一 LCG（§7）。
        let fallbackHigh = Self.nextHighBits(random)

        if param3 <= 0 {
            throw ChallengeFruitSelectionError.emptyCandidates
        }
        if param3 < 2 {
            throw ChallengeFruitSelectionError.unsafeFallback(count: param3,
                                                              unscaledIndex: fallbackHigh)
        }

        let index = ChallengeFruitSelectionMath.fallbackIndex(high: fallbackHigh, count: param3)
        guard UInt64(index) < UInt64(candidates.count) else {
            throw ChallengeFruitSelectionError.fallbackIndexOutOfBounds(count: param3,
                                                                        index: index)
        }
        return candidates[Int(index)]
    }

    // MARK: 新建挑战（FUN_00061128，param_2 == 0）

    /// 新建挑战路径：先默认初选，再按 `challengeFruitSize` 覆盖。
    ///
    /// 顺序来自 challenge_fruit_selection... §4：
    /// 1. `FUN_0000af50` 默认初选写入 `controller + 0x88`（**会消耗一次选择**）。
    /// 2. 模式 1/2/3 调用对应选择函数并覆盖 `controller + 0x88`（**再消耗一次**）。
    ///
    /// ⚠️ 第二次选择时 `T_all > 0`，原版不会重建（§4 缓存边界）：它用**全水果**的
    ///    `T_free/T_flagFree` 与 `+0x30c/+0x310` 缓存去扫描**模式子集**候选，
    ///    roll 可能大于子集累计和而落入回退。这是原版真实行为，必须保留。
    public mutating func selectNewGameChallengeFruit(

                                              finalSelection: finalSelection,
                                              appliedMode: size)

    // MARK: PRNG

    /// 推进一次 64 位 LCG 并返回**新状态高 32 位**（原版内联 LCG 的 `H`）。
    ///
    /// `OriginalLCGRandom.nextInt(_:)` 在 `upperBound <= 0` 时返回
    /// `Int32(bitPattern: state >> 32)` 且不做缩放，恰好等于原版一次推进得到的 `H`。

    private static func nextHighBits(_ random: RandomSource) -> UInt32 {
        UInt32(bitPattern: random.nextInt(0))
    }

## Kimi 审查注意的风险点

1. **`RandomSource.nextInt(0)` 语义耦合（最重要）**：`nextHighBits` 依赖 `OriginalLCGRandom` 在 `upperBound <= 0` 时返回"新状态高 32 位且不缩放"。协议本身没有书面契约；若将来新增 `RandomSource` 实现，选择器会静默偏离原版 PRNG 流。建议后续在协议层显式加 `nextUInt32HighBits()`（本卡未改协议）。
2. **名称匹配精度**：原版 `FUN_0000aae0` 先经 `FUN_002f69c4` 规范化/哈希名称再比较 `+0x250`；本实现用 `FruitInfo.name` 精确字符串相等。大小写/Unicode 规范化差异未闭合 [待验证]。
3. **缓存键为 `typeID`**：原版写回每个 FruitInfo 槽位；同一 ID 在候选数组重复出现时，后写覆盖前写，扫描时两次读到同一最终值。本实现忠实复刻该覆盖语义，但请确认调用方不会把重复 ID 候选当作"两次独立权重"。
4. **`unsafeFallback` / `emptyCandidates` 是新增策略**：原版对空候选与"进入回退的单候选"是 `param_2[H2]` 越界，无合法返回值；单候选在 `H2 == 0` 时恰好未越界，本实现仍拒绝，属刻意保守，需审查是否接受。
5. **`selectNewGameChallengeFruit` 的共享缓存怪行为**：模式覆盖阶段 `T_all > 0` 跳过重建，`N` 用全水果总量、扫描用模式子集，roll 可能落入回退。这是原版真实行为（证据 §4「缓存边界」），但极易被后续调用方误用；建议在 App/挑战控制器接入时加注释。
6. **P 未求值**：`predicateP` 由调用方注入；`FUN_0005809c` 的 `M/F/C` 全局状态求值不在本卡范围。官方新局默认 0 只写在注释里，未被代码强制。
7. **`typeID` 与 catalog 索引一致性假设**：原版候选数组写的是 FruitInfo 数组索引；本实现按任务卡要求输出 `FruitInfo.typeID`。生产加载必须保证 `typeID == 文档零基序号`（ContentTypes 注释已如此约定），否则候选 ID 语义偏移。
8. **未编译验证**：本机 Windows 无 Xcode；`RandomSource` 协议签名、`FNPBCore` 模块名、测试 target 名均按仓库既有约定推断，需 Mac/CI 首编译确认。
