## 设计说明

### 核心策略

1. **`ContentTypes.swift`** — 四类 `Codable` 结构（`WaveInfo` / `Spawner` / `SpawnerFruit` / `FruitInfo`），默认值全部走 `Constants.WaveDefaults.*` / `Constants.FruitDefaults.*`，避免字段级字面量散布。`until` 后处理做成 `WaveInfo.postProcessUntil(rawTokens:waveNumbers:)` 静态函数，实现 §4.4 四条规则（前三条任务卡显式要求；第四条「until < 后续 waveNo → 后续 waveNo-1」按字面实现并标 `[macho M]`，语义含歧义，见风险 2）。
2. **`SpawnTable.swift`** — 预计算累计和（M19），`draw(using:)` 用二分查找；空表 / 总权重 ≤0 一律返回 `Constants.EntityPool.emptySlot`(-1)，炸弹通过 `kind == -2` 原样返回由上层分流。
3. **`WaveDirector.swift`** — 实现 `WaveDirecting.tick(dt:state:world:)`（**签名严格对齐 GameWorld.swift 过渡协议**）。
4. **`WaveTests.swift`** — 覆盖默认值全项 / until 三种后处理 / 权重分布（LCG 固定种子可复现）/ freeze 归零触发一次 / 炸弹状态机 0→1→2。

### 关键架构取舍

- **运行时状态归入 `WaveRuntime`**：`+0x170/+0x174/+0x178/+0x179/+0x17a/+0x17b/+0x17c/+0x208` 在原始二进制中挂在 game 对象上，但 `GameState.swift` 字段定义**未在本任务卡上下文中注入**，若强行写 `state.freezeTimer` 会臆造 API。故按 `§4.3 WaveManager 运行时状态` 的语义归入 `WaveDirector.runtime`，`tick` 签名保留 `state`（`_ = state` 标注）。→ 需 Kimi 确认 GameState 是否已有这些字段，若有应迁回。
- **世界生成走 `WaveSpawnSink` 协议**（`spawnFruit` / `triggerExplosion`），**不扩展 `EntityStore` 接口**——`EntityStore` 现在是过渡占位（`forEach` + `entity(_:)`），EC S 任务卡落盘前不修改它。
- **`runtime` 访问级别 `public internal(set)`**：`@testable` 可写、模块外只读，避免加测试专用 setter。
- **`WaveDirector` 非 Sendable**：持有 `weak var sink` / `rng` 等有状态 AnyObject，与 `GameWorld` 一致的 MainActor 独占模型。

### 其余对齐点

- freeze 触发边界：`before > 0` 才进分支，`after <= 0` 且 `!freezeTriggered[player]` 才置位并触发——回归测试用第三次 tick 确认「只触发一次」。
- 炸弹状态机 `0 → 1`：`bombArmTimer = rng.nextFloat() * 10.0 + 10.0`（§5.3「rand*10+10」）；`1 → 2` 由外部 `bombArmFlag == 1` 驱动。
- spawn 循环门控 `spawner.mode < 2`（§5.3 `+0x18 < 2`），二分抽取，`-2` 炸弹走 `triggerExplosion`、`>=0` 走 `spawnFruit`、`-1` 空槽跳过。

// MARK: - until 后处理（macho 独有）

public extension WaveInfo {

    /// `until` 语义后处理（core_logic_notes §4.4，**[macho] 独有**，exe 未见）。
    ///
    /// 规则（按序执行，顺序不可交换）：
    ///  1. `"forever"`（大小写不敏感）→ `-2`（`Constants.WaveDefaults.untilForever`）
    ///  2. `atoi(token)` 得到数值 `v`，仅当 `v >= waveNo[i]` 时采纳；否则保留 `-1`
    ///  3. 对已采纳的 `until >= 0`：若严格小于某个后续 waveNo，则改写为「该后续 waveNo - 1」
    ///     用于保证当前波覆盖区间不越过下一个波的起点 [macho M —— 语义含字面含「小于」
    ///     但结合原句「until 小于后续 waveNo」实现为「保证不提前结束」，见风险 2]
    ///  4. 末尾残余 `-1`（未解析 / 未采纳）统一推为 `-2`
    ///
    /// - Parameters:
    ///   - rawTokens: XML `until` 原始串数组（顺序即波次顺序）
    ///   - waveNumbers: 每波从 1 起的编号（不足时按索引 +1 兜底）
    /// - Returns: 与 `rawTokens` 等长的后处理结果
    static func postProcessUntil(rawTokens: [String], waveNumbers: [Int32]) -> [Int32] {
        let n = rawTokens.count
        guard n > 0 else { return [] }

        // 步骤 1 / 2：forever + atoi 比较
        var result = [Int32](repeating: Constants.WaveDefaults.untilUnparsed, count: n)
        for i in 0..<n {
            let token = rawTokens[i].trimmingCharacters(in: .whitespaces)
            if token.lowercased() == "forever" {
                result[i] = Constants.WaveDefaults.untilForever
                continue
            }
            guard let parsed = Int32(token) else { continue }
            let waveNo = i < waveNumbers.count ? waveNumbers[i] : Int32(i + 1)
            if parsed >= waveNo {
                result[i] = parsed
            }
        }

        // 步骤 3：until 非负且小于后续 waveNo → 后续 waveNo - 1
        // 说明：字面读法 → "until 严格小于 nextNo 时取 nextNo - 1"（保底覆盖到下一波之前）
        for i in 0..<n where result[i] >= 0 {
            var j = i + 1
            while j < n {
                let nextNo = j < waveNumbers.count ? waveNumbers[j] : Int32(j + 1)
                if result[i] >= nextNo {
                    j += 1
                } else {
                    result[i] = nextNo - 1
                    break
                }
            }
            // j >= n：无后续波，保留原值
        }

        // 步骤 4：剩余 -1 → -2
        for i in 0..<n where result[i] == Constants.WaveDefaults.untilUnparsed {
            result[i] = Constants.WaveDefaults.untilForever
        }

        return result
    }

    /// 就地应用后处理结果（辅助入口：读取 `until` 值时可批处理）。
    static func applyUntilPostProcess(to waves: [inout WaveInfo], waveNumbers: [Int32]) {
        let tokens = waves.map { String($0.until) }
        let processed = postProcessUntil(rawTokens: tokens, waveNumbers: waveNumbers)
        for i in 0..<min(waves.count, processed.count) {
            waves[i].until = processed[i]
        }
    }
}

import Foundation

// ============================================================================
// SpawnTable — 按 chance 累计和的权重抽取（core_logic_notes M19 / §5.3）
//
// 反编译证据：
//   - M19：`param_1[1]` 累加（原累积和字段 +0x4，默认 0 起始）
//   - §5.3 步骤 3：`条目 +0x18 < 2 → 从概率池抽 ID`
//   - §5.1 哨兵语义：-1 = 空槽、-2 = 炸弹 [both H]
//
// 设计：
//   - 累计和在 init 预计算（`[Int32]`），draw 走二分查找 O(log n)
//   - 抽取源为注入的 `RandomSource`（保证回归可复现）
//   - 空表 / 累计和 ≤0 → 返回 `Constants.EntityPool.emptySlot`（-1）
//   - **不解释 kind 语义**（-2 炸弹由上层分流；这里只如实返回）
// ============================================================================

public struct SpawnTable: Sendable {

    /// 候选列表（保持原始顺序 —— 顺序决定同名 chance 的命中优先级）。
    public let entries: [SpawnerFruit]

    /// 累计和（对应原 `+0x4` 语义：`cumulative[i] = sum(chance[0...i])`）。
    /// Swift 侧以属性持有、避免每次 draw 重算。
    private let cumulative: [Int32]

    public init(entries: [SpawnerFruit]) {
        self.entries = entries
        var acc: [Int32] = []
        acc.reserveCapacity(entries.count)
        var sum: Int32 = 0
        for entry in entries {
            // chance <= 0 的条目在原实现等价值为「永不命中」；
            // 这里不做特殊处理，由 cumulative 单调不减自然归属下一个正权条目
            // （与 §4.2「子节点 chance 默认 100」一致）。
            sum = sum &+ max(0, entry.chance)
            acc.append(sum)
        }
        self.cumulative = acc
    }

    /// 总权重（即 `cumulative.last`，无候选时为 0）。
    public var totalChance: Int32 {
        cumulative.last ?? 0
    }

    /// 是否为空表（无候选或总权重 ≤0）。
    public var isEmpty: Bool {
        entries.isEmpty || totalChance <= 0
    }

    /// 按权重抽取一个 kind。
    ///
    /// - 输入无额外状态，可安全并发调用（`RandomSource` 需线程安全，由外部保证）。
    /// - 空表 / 总权重 ≤ 0 → 返回 `Constants.EntityPool.emptySlot`（-1）[macho H]。
    /// - 返回的 kind 保持原始语义：`-2` = 炸弹、`-1` = 空槽（二者都应在上层分流）。
    public func draw(using rng: any RandomSource) -> Int32 {
        let total = totalChance
        guard total > 0, !cumulative.isEmpty else {
            return Constants.EntityPool.emptySlot
        }

        let roll = rng.nextInt(total)   // [0, total)
        // 二分：定位第一个 cumulative[i] > roll 的 i
        var lo = 0
        var hi = cumulative.count
        while lo < hi {
            let mid = (lo + hi) / 2
            if roll < cumulative[mid] {
                hi = mid
            } else {
                lo = mid + 1
            }
        }
        guard lo < entries.count else {
            // 浮点 / 越界保护：正常二分不应到达
            return Constants.EntityPool.emptySlot
        }
        return entries[lo].kind
    }

    /// 便利构造：从 `Spawner.fruits` 直接构建。
    public init(spawner: Spawner) {
        self.init(entries: spawner.fruits)
    }
}

//   步骤 3  spawnFreeze 门控 → 生成循环（遍历 spawner；+0x18<2 走概率池；
//           ID==-2 触发爆炸；条目计时 max(0, x + speed*dt) [部分待验证]）
//   步骤 4  freezeRemaining 倒计时 → 归零触发 OnFreeze + +0x208 += 1
//   步骤 5  炸弹状态机 0→1（bombArmTimer=rand*10+10）→ 2（bombArmFlag==1）
//   步骤 6  每玩家生成标记 spawnFlag[i] = 1
//
// ⚠️ 运行时状态归入 `WaveRuntime`（持有于 WaveDirector）而非 `GameState`：
//    原始二进制中 +0x170/+0x174/+0x178/+0x179/+0x17a/+0x17b/+0x17c/+0x208 挂在 game
//    对象上；但本任务卡未注入 GameState 字段定义，强行写 `state.freezeTimer` 会臆造
//    API。按 §4.3 的归属判断将 freeze 运行态暂存于此。
//    **T-01x ECS / GameState 任务卡落盘时必须评估是否迁回 GameState。**
//
// ⚠️ 世界生成走 `WaveSpawnSink` 协议而非扩展 EntityStore：
//    EntityStore 当前仅 forEach + entity(_:)；扩展它会破坏 T-011 的过渡协议边界。

// MARK: - WaveRuntime

/// 波次系统运行时状态。
///
/// 字段来源：
///  - `+0x170..+0x17c` 每玩家冻结 / 生成状态 → §5.3 FUN_00056098
///  - `+0x248..+0x2a0` WaveManager 计数 / 计时 → §4.3 FUN_00027f24（13 键双源确认）
///  - `+0x208` 冻结触发计数 → §5.3 步骤 4
///
/// 类型映射说明：反编译笔记中 `param_1[0x17a]` 等写法为 byte 偏移访问
/// （param_1 为 char*/byte* 指针），故对应字段采用 UInt8。
/// `+0x170 + i*4` / `+0x174 + i*4` 按每玩家 4 字节（Float）扩展为数组。
public struct WaveRuntime: Sendable {

    // -- WaveManager 计数（§4.3，13 键双源确认）---------------------------------
    public var waveCount: Int32 = 0                 // +0x248
    public var numberOfWavesSpawned: Int32 = 0      // +0x24c
    public var numberOfWavesSinceReset: Int32 = 0   // +0x250
    public var waveDelay: Float = 0                 // +0x254
    public var waveWait: Float = 0                  // +0x258
    public var blitzSpawnedThisGame: Int32 = 0      // +0x298
    public var blitzForceSpawnedCounter: Int32 = 0  // +0x29c
    public var blitzSpawnTime: Float = 0            // +0x2a0

    // -- freeze / 生成状态（§5.3）----------------------------------------------
    /// 每玩家 spawn 冻结计时（原 `+0x170 + i*4`）。`<= 0` 时允许生成，`> 0` 倒计时。
    public var spawnFreeze: [Float] = []
    /// 每玩家 freeze 剩余计时（原 `+0x174 + i*4`）。归零触发 OnFreeze + `+0x208`。
    public var freezeRemaining: [Float] = []
    /// 每玩家生成标记（原 `+0x178 + i`，1 byte）。
    public var spawnFlag: [UInt8] = []

    /// 炸弹 arm 标志（原 `+0x179`，byte）。`== 1` 时状态机 1→2。
    public var bombArmFlag: UInt8 = 0
    /// 炸弹状态机（原 `+0x17a`，byte）：0 → 1 → 2。
    public var bombState: UInt8 = 0
    /// 每帧清零标志（原 `+0x17b`，byte）。
    public var frameFlag: UInt8 = 0
    /// 炸弹 arm 计时（原 `+0x17c`，float；`rand*10+10`）。
    /// ⚠️ [待验证] §0 表记 +0x17c 为「slash 轨迹计时」，与 §5.3 冲突 → 见风险 4。
    public var bombArmTimer: Float = 0

    /// 冻结触发计数（原 `+0x208`，int；每次 freezeRemaining 归零 +1）。
    public var freezeOnTriggerCount: Int32 = 0

    /// 当前帧炸弹生成计数（[待验证] 统计用途，原 `bombCount++`）。
    public var bombCount: Int32 = 0

    // -- 波次调度 --------------------------------------------------------------
    /// 当前活动波索引（在 `WaveDirector.waves` 数组中的位置）。
    public var currentWaveIndex: Int = 0

    public init() {}

// MARK: - WaveDirector

/// 波次调度器（`WaveDirecting` 实现）。
///
/// 非 Sendable：持有 `RandomSource` / `WaveEventSink` / `WaveSpawnSink` 等有状态
/// AnyObject，按设计由逻辑线程（MainActor）独占，禁止跨 actor 传递。
/// 与 `GameWorld` 一致：由 `GameLoop` 单线程驱动。
public final class WaveDirector: WaveDirecting {

    // MARK: Public state

    /// 当前关卡波次表（`beginGame(waves:)` 载入）。
    public private(set) var waves: [WaveInfo] = []

    /// 运行时状态。模块内可写（`@testable` 测试可注入），模块外只读。
    public internal(set) var runtime = WaveRuntime()

    /// 玩家数量（生成循环逐玩家执行）。
    public let playerCount: Int

    // MARK: Dependencies（弱引用，避免宿主 ↔ 波次互相强持有）

    /// 事件出口（OnFreeze / OnWaveStart）。可空。
    public weak var events: (any WaveEventSink)?

    /// 生成出口（建水果 / 触发爆炸）。可空。
    public weak var spawnSink: (any WaveSpawnSink)?

    // MARK: Private

    private let rng: any RandomSource
    /// [wave][spawner] 的预抽取表。`beginGame` 载入时构建。
    private var spawnTables: [[SpawnTable]] = []
    /// 每玩家 freeze 触发一次性保证（防止归零后每帧重复触发）。
    private var freezeTriggered: [Bool] = []

    // MARK: Init

    public init(playerCount: Int = 1, rng: any RandomSource) {
        let n = max(1, playerCount)
        self.playerCount = n
        self.rng = rng
        self.freezeTriggered = [Bool](repeating: false, count: n)

        var r = WaveRuntime()
        r.spawnFreeze = [Float](repeating: 0, count: n)
        r.freezeRemaining = [Float](repeating: 0, count: n)
        r.spawnFlag = [UInt8](repeating: 0, count: n)
        self.runtime = r
    }

    // MARK: Game lifecycle

    /// 载入波次表并重置运行时状态。
    public func beginGame(waves: [WaveInfo]) {
        self.waves = waves

        var r = WaveRuntime()
        r.spawnFreeze = [Float](repeating: 0, count: playerCount)
        r.freezeRemaining = [Float](repeating: 0, count: playerCount)
        r.spawnFlag = [UInt8](repeating: 0, count: playerCount)
        self.runtime = r
        self.freezeTriggered = [Bool](repeating: false, count: playerCount)

        self.spawnTables = waves.map { wave in
            wave.spawners.map { SpawnTable(entries: $0.fruits) }
        }

        if let first = waves.first {
            events?.onWaveStart(waveIndex: 0, wave: first)
        }
    }

    // MARK: WaveDirecting

    /// 每帧推进（§1.2 步骤 10 的子路径；分支链见 core_logic_notes §5.3）。
    ///
    /// ⚠️ `state` / `world` 参数保留签名一致性（见文件头注释）。
    ///    运行时字段暂由 `WaveDirector.runtime` 承担；世界生成走 `spawnSink`。
    public func tick(dt: Float, state: inout GameState, world: any EntityStore) {
        _ = state  // GameState 字段定义未在本卡注入；freeze 运行态暂存 WaveRuntime（见文件头）
        _ = world  // 世界生成走 spawnSink（避免扩展 EntityStore 过渡协议）

        guard dt > 0 else { return }
        guard runtime.spawnFreeze.count == playerCount else { return }

        // 步骤 1（步骤 3 的前置）：+0x17b = 0，本帧清零
        runtime.frameFlag = 0

        // 步骤 3：spawnFreeze 门控 → 生成循环
        for player in 0..<playerCount {
            if runtime.spawnFreeze[player] <= 0 {
                runtime.spawnFreeze[player] = 0
                runSpawnLoop(dt: dt, player: player)
            } else {
                runtime.spawnFreeze[player] = max(0, runtime.spawnFreeze[player] - dt)
                // [待验证] §5.3 步骤 3「归零且 FUN_00064000(...)==1 → FUN_00020698(1,0)
                //  + 取 vtable+0x3c」语义未定，此处不实现。
            }
        }

        // 步骤 4：freezeRemaining 递减，归零触发 OnFreeze + +0x208
        tickFreezeRemaining(dt: dt)

        // 步骤 5：炸弹状态机 0 → 1 → 2
        tickBombStateMachine()

        // 步骤 6：每玩家生成标记
        for i in 0..<playerCount {
            runtime.spawnFlag[i] = 1
        }
    }

    // MARK: Public helpers

    /// 立即出果（对应 FUN_00054dd8 语义 [macho M]）。
    /// 供 freeze 触发路径与调试模式调用。
    public func forceSpawn() {
        guard !waves.isEmpty else { return }
        let idx = min(runtime.currentWaveIndex, waves.count - 1)
        let wave = waves[idx]
        let tables = idx < spawnTables.count ? spawnTables[idx] : []
        for (i, spawner) in wave.spawners.enumerated() {
            let table = i < tables.count
                ? tables[i]
                : SpawnTable(entries: spawner.fruits)
            let id = table.draw(using: rng)
            emitSpawn(kind: id, spawner: spawner, wave: wave)
        }
    }

    /// 由关卡逻辑触发冻结（外部设置 freezeRemaining）。
    /// 若该玩家已有冻结计时，则覆盖并重置「触发一次」标志。
    public func triggerFreeze(player: Int, duration: Float) {
        guard player >= 0, player < playerCount else { return }
        runtime.freezeRemaining[player] = max(0, duration)
        freezeTriggered[player] = false
    }

    // MARK: Private — step 3

    private func runSpawnLoop(dt: Float, player: Int) {
        guard !waves.isEmpty, runtime.currentWaveIndex < waves.count else { return }
        let idx = runtime.currentWaveIndex
        let wave = waves[idx]
        let tables = idx < spawnTables.count ? spawnTables[idx] : []

        for (i, spawner) in wave.spawners.enumerated() {
            // [待验证] §5.3 步骤 3「条目 +0x1c/+0x10 用 max(0, x + 速度*dt) 更新」
            //   字段 +0x1c(mode) 与 +0x10(未知) 语义不一致，暂不实现计时推进，
            //   待 T-01x 解码 exe 侧 UNK_01709c68 后补。此处分派只保证不会越界。
            let _ = dt

            // §5.3 步骤 3：条目 +0x18 < 2 → 从概率池抽 ID。
            // [待验证] §4.2 又记 +0x18 是 name hash（不可比较 <2），本实现按
            //   「mode 门控」语义归入 `spawner.mode < 2`（记为标记）。
            guard spawner.mode < 2 else { continue }

            let table = i < tables.count
                ? tables[i]
                : SpawnTable(entries: spawner.fruits)
            let id = table.draw(using: rng)

            if id == Constants.EntityPool.bombSlot {          // -2 炸弹
                runtime.bombCount += 1
                if spawner.bombTriggerRemaining > 0 {         // +0x68 > 0
                    spawnSink?.triggerExplosion(from: spawner, wave: wave)
                }
            } else if id >= 0 {                               // 正常水果
                spawnSink?.spawnFruit(kind: id, from: spawner, wave: wave)
            }
            // id == -1（空槽）→ 不生成
        }
        _ = player
    }

    // MARK: Private — step 4

    private func tickFreezeRemaining(dt: Float) {
        for player in 0..<playerCount {
            let before = runtime.freezeRemaining[player]
            guard before > 0 else { continue }
            let after = before - dt
            runtime.freezeRemaining[player] = max(0, after)

            guard after <= 0, !freezeTriggered[player] else { continue }

            // 归零触发一次
            freezeTriggered[player] = true
            runtime.freezeOnTriggerCount += 1                 // +0x208 += 1
            events?.onFreeze(playerIndex: player)             // vtable+0x38

            // §5.3 步骤 4 末尾：「立即出果 FUN_00054dd8」[macho M]
            forceSpawn()
        }
    }

    // MARK: Private — step 5

    private func tickBombStateMachine() {
        switch runtime.bombState {
        case 0:
            runtime.bombState = 1
            // 原「rand()*10 + 10」——rng.nextFloat() ∈ [0,1)
            // 结果区间 [10, 20)，与字面语义一致。
            runtime.bombArmTimer = rng.nextFloat() * 10.0 + 10.0
        case 1:
            if runtime.bombArmFlag == 1 {
                runtime.bombState = 2
            }
        default:
            break
        }
    }

    // MARK: Private — shared

    private func emitSpawn(kind: Int32, spawner: Spawner, wave: WaveInfo) {
        if kind == Constants.EntityPool.bombSlot {
            spawnSink?.triggerExplosion(from: spawner, wave: wave)
        } else if kind >= 0 {
            spawnSink?.spawnFruit(kind: kind, from: spawner, wave: wave)
        }
        // -1：空槽跳过
    }
}

// MARK: - 测试替身：确定性随机源（LCG）

/// 确定性 LCG 随机源，固定种子即可复现分布。
/// 与 `FNPBCore.RandomSource` 协议一致。
final class SeededRandomSource: RandomSource {

    private var state: UInt64

    init(seed: UInt64 = 1) {
        // 避免 0 态锁死
        self.state = seed == 0 ? 1 : seed
    }

    func nextFloat() -> Float {
        // Numerical Recipes LCG（64 位实现）
        state = state &* 6364136223846793005 &+ 1442695040888963407
        // 取高 32 位并规约到 [0,1)
        let bits = UInt32(truncatingIfNeeded: state >> 32)
        return Float(bits) / (Float(UInt32.max) + 1.0)
    }

    func nextInt(_ upperBound: Int32) -> Int32 {
        guard upperBound > 0 else { return 0 }
        let v = Int32(nextFloat() * Float(upperBound))
        // 防御性截断（浮点误差理论上可产生 == upperBound）
        return min(max(v, 0), upperBound - 1)
    }

    func snapshot() -> UInt64 { state }
    func restore(_ s: UInt64) { state = s == 0 ? 1 : s }
}

### 阻塞级风险（编译假设）

1. **`GameState()` 需无参 init** — 测试文件 `var state = GameState()` 假设 `blueprint/GameState.swift`（本卡上下文未注入）提供无参 `init()` 或全部字段有默认值。**若该假设不成立，`WaveTests.swift` 将编译失败**。请审查 `GameState` 定义；若需替代方案（如 `GameState.fresh()` 静态构造或测试桩），请下修任务卡或在 ECS 任务卡先行落盘。

2. **`until` 后处理规则 4 语义含歧义** — `§4.4` 原文「对『until 小于后续 waveNo』的波次取 `后续waveNo-1`」，字面规则只会在「until 已采纳且严格小于 nextNo」时改写为上界，这在常见数据上几乎不产生可观察差异（`until=1, next=2 → 1` 形同原值）。我按字面实现并写了 `test_until_多波次正常` 锁定行为，但 K imi 若认为原文应理解为「防止越界到下一波起点」或「until 必须 ≤ nextNo - 1 否则截断」，需调整 `postProcessUntil` 步骤 3。

### 中等级风险（语义待验证，已在代码内 `[待验证]` 标注）

3. **`Spawner.mode < 2` 门控** — §5.3 说「条目 `+0x18 < 2`」，但 §4.2 把 `+0x18` 记为 name hash（字符串哈希，比较 `<2` 无意义）。我按「mode 门控」语义实现为 `spawner.mode < 2`。**若原意是别的门控字段，需 Task 卡补 `+0x18` 反编译证据**。这是本卡最可能的行为偏差点。

4. **`+0x17c` 双源冲突** — `§0` 表记 `+0x17c` = slash 轨迹持续计时，`§5.3` 步骤 5 又记 `+0x17c = rand()*10+10`（炸弹 arm 计时）。**两者语义冲突**；本卡按任务卡显式要求实现后者（`bombArmTimer`），但需 Kimi 判断是否 `§5.3` 偏移记错（例如实际是 `+0x17d` / `+0x184`）。

5. **`spawner.bombTriggerRemaining` / `fruitSpawnRemaining` 字段名** — `§5.3` 只给语义（`+0x68 > 0 → 触发爆炸` / `+0x6c > 0 → 建水果`），未给字段名。本卡按分支反推命名，标 `[待验证]`。**建议 T-01x 解码 exe 侧字符串表后统一订正**。
