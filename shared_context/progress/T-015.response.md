## 设计说明

**迁移方案**

- `EntityID / EntityKind / EntityTransform / Entity / EntityPrototype` 全部落到 `Sources/FNPBCore/ECS/Entity.swift`，`EntityStore` 协议 + `GenerationOrderStore` 落到 `ECS/EntityStore.swift`；`GameWorld.swift` 中过渡节整节删除（包括其中的 `EntityStore` 协议），10 步桩与依赖协议节**逐字保留**。
- 同 target 说明：FNPBCore 是单一 target，`Loop/` 与 `ECS/` 同模块，Swift 内不能 `import` 自身模块（会报 no such module），因此采用「同模块直接引用」，若未来拆子模块再加 `import FNPBCoreECS`。这是对任务卡「改为 import 引用 ECS 模块」的必要偏离。
- `EntityStore` 协议新增蓝图 S2 全签名 `spawn/despawn/entity/forEach/aliveCount/clear`；`forEach(kind:)` 保留为协议要求 + 扩展默认实现（按生成序过滤），保证 `any EntityStore` 动态派发下行为一致。
- `GenerationOrderStore` 用**数组存槽位**保证生成序遍历，Dictionary 仅作 id→下标索引（不做遍历）；despawn 打墓碑不搬移，超过阈值才压缩并重建索引，id 单调递增永不复用。
- `FruitMotion` 采用**半隐式欧拉**（先更新速度再更新位置），便于手算与回归；所有可调参数收进 `FruitMotionTuning`，默认值来自 `Constants.Physics` 占位（在 `FruitMotion.swift` 里以 `extension Constants` 声明，避免本卡触碰 `Constants.swift`）。重力/初速/发射角/离屏阈值**全部 `[待验证]`**。

import Foundation

// ============================================================================
// EntityStore — ECS 容器协议与生成序实现（T-015，蓝图 §3 S2）
//
// 顺序约束（不可违反）：
//   原主循环按「生成顺序」遍历实体（引擎迭代器 0x065c4/0x06ad0/0x06af0 的单向链表语义），
//   因此任何实现都必须提供**确定性的生成序遍历**。
//   ⚠️ 禁止用 Dictionary 直接遍历实现 forEach —— Swift Dictionary 无序，
//      会破坏 combo 计数、特效触发顺序与回放一致性。
//
// 遍历语义：
//   - `forEach(_:)`：按生成序遍历全部存活实体；body 返回 false 立即终止。
//   - `forEach(kind:_:)`：同一生成序中筛选指定 kind 的子序列（等价于原主循环
//     循环 A/B/C 各自按 type 过滤），默认实现为 O(n) 过滤，实体数在数量级 10~100，
//     暂不做按 kind 分桶（分桶会引入额外的顺序维护成本）。
// ============================================================================

// MARK: - 协议

public protocol EntityStore: AnyObject {

    /// 生成实体并返回其 id。id 单调递增、despawn 后不复用。
    @discardableResult
    func spawn(_ prototype: EntityPrototype) -> EntityID

    /// 回收实体。对不存在/已回收的 id 为空操作。
    func despawn(_ id: EntityID)

    /// 查询实体快照（值拷贝）。不存在或已回收返回 nil。
    func entity(_ id: EntityID) -> Entity?

    /// 按生成序遍历所有存活实体。
    /// - Parameter body: 返回 false 终止遍历；对实体字段的修改在遍历结束前写回。
    func forEach(_ body: (inout Entity) -> Bool)

    /// 按生成序遍历指定 kind 的存活实体（原主循环循环 A/B/C 的筛选语义）。
    func forEach(kind: EntityKind, _ body: (inout Entity) -> Bool)

    /// 存活实体数。
    var aliveCount: Int { get }

    /// 清空所有实体（不移位、不重置 id 分配器）。
    func clear()
}

public extension EntityStore {

    func contains(_ id: EntityID) -> Bool { entity(id) != nil }

    func forEach(kind: EntityKind, _ body: (inout Entity) -> Bool) {
        forEach { (entity: inout Entity) -> Bool in
            guard entity.kind == kind else { return true }
            return body(&entity)
        }
    }
}

// MARK: - 生成序实现

/// 数组槽位 + id 索引的确定性实体容器。
///
/// 实现要点：
/// 1. 存储主结构是 `slots` 数组，**数组下标顺序 = 生成顺序**；
/// 2. `indexByID` 只用于 O(1) 定位，**从不用于遍历**；
/// 3. despawn 打墓碑（`isAlive = false`），不搬移其他元素 → 存活实体的相对顺序恒定；
/// 4. 墓碑累积到阈值后压缩一次，压缩保留相对顺序并重建索引，id 不变；
/// 5. `nextRawValue` 单调递增且跳过 0，clear 后也不回收已用 id（保证测试/回放的
///    「id 稳定」语义）。
public final class GenerationOrderStore: EntityStore {

    private struct Slot {
        var entity: Entity
        var isAlive: Bool = true
    }

    /// 墓碑压缩阈值：dead 数达到该值且占比过半时压缩。
    /// 取 16 是「实体数 10~100」量级下的经验值，仅影响内存与遍历常数，不影响语义。
    private static let compactionDeadThreshold = 16

    private var slots: [Slot] = []
    private var indexByID: [EntityID: Int] = [:]
    private var nextRawValue: UInt32 = 1
    private var deadCount = 0

    public init() {}

    public var aliveCount: Int { slots.count - deadCount }

    // MARK: spawn / despawn

    @discardableResult
    public func spawn(_ prototype: EntityPrototype) -> EntityID {
        let id = EntityID(rawValue: nextRawValue)
        advanceRawValue()

        var entity = Entity(id: id, kind: prototype.kind)
        entity.transform = prototype.transform
        entity.fruit = prototype.fruit

        slots.append(Slot(entity: entity))
        indexByID[id] = slots.count - 1
        return id
    }

    public func despawn(_ id: EntityID) {
        guard let index = indexByID.removeValue(forKey: id), slots[index].isAlive else { return }
        slots[index].isAlive = false
        deadCount += 1
        compactIfNeeded()
    }

    // MARK: 查询

    public func entity(_ id: EntityID) -> Entity? {
        guard let index = indexByID[id], slots[index].isAlive else { return nil }
        return slots[index].entity
    }

    // MARK: 遍历

    public func forEach(_ body: (inout Entity) -> Bool) {
        // 先取 id 快照：body 内部允许 spawn/despawn（不改变已生成实体的相对顺序），
        // 用 id 重查槽位可避免压缩导致的下标错位。
        let snapshotIDs: [EntityID] = slots.compactMap { $0.isAlive ? $0.entity.id : nil }

        for id in snapshotIDs {
            guard let index = indexByID[id], slots[index].isAlive else { continue }

            var snapshot = slots[index].entity
            let shouldContinue = body(&snapshot)

            // 写回前重新定位：body 可能触发了压缩。
            if let currentIndex = indexByID[id],
               slots[currentIndex].isAlive,
               slots[currentIndex].entity.id == id {
                slots[currentIndex].entity = snapshot
            }

            if !shouldContinue { return }
        }
    }

    // MARK: clear

    public func clear() {
        slots.removeAll(keepingCapacity: false)
        indexByID.removeAll(keepingCapacity: false)
        deadCount = 0
        // nextRawValue 故意不重置：已分配 id 永不复用。
    }

    // MARK: 内部

    private func advanceRawValue() {
        if nextRawValue == UInt32.max {
            nextRawValue = 1    // 回绕并跳过 0（0 = invalid）
        } else {
            nextRawValue += 1
        }
    }

    private func compactIfNeeded() {
        guard deadCount >= Self.compactionDeadThreshold,
              deadCount * 2 >= slots.count else { return }
        slots.removeAll { !$0.isAlive }
        deadCount = 0
        rebuildIndex()
    }

    private func rebuildIndex() {
        indexByID.removeAll(keepingCapacity: true)
        for (index, slot) in slots.enumerated() where slot.isAlive {
            indexByID[slot.entity.id] = index
        }
    }
}

public enum FruitMotion {

    /// 推进一个逻辑步。
    ///
    /// - Parameters:
    ///   - entity: 被推进的实体（原地修改 position/velocity/rotation）。
    ///   - dt: 步长（秒）。`dt <= 0` 时只做存活判定，不推进。
    ///   - tuning: 参数集合。
    /// - Returns: `false` 表示实体已离屏、应被 `EntityStore.despawn` 回收。
    ///
    /// 注意：本函数**不**处理「被切中」后的形态切换（fruit → jiblet），
    /// 那属于切割/特效层（§1.2 步骤 6.3）；也不消费 `Entity.dropState`（原 +0x41 下落态
    /// 的语义仍为 [M] 级，未闭合，故不在积分器里使用）。
    @discardableResult
    public static func integrate(_ entity: inout Entity,
                                 dt: Float,
                                 tuning: FruitMotionTuning) -> Bool {
        guard dt > 0 else { return isAlive(entity, tuning: tuning) }

        // 半隐式欧拉：先速度、后位置。
        entity.transform.velocity.y += tuning.gravity * dt
        entity.transform.position += entity.transform.velocity * dt
        entity.transform.rotation += entity.transform.angularVelocity * dt

        return isAlive(entity, tuning: tuning)
    }

        if p.y < tuning.offscreenBottomMargin { return false }
        if p.y > tuning.offscreenTopLimit { return false }
        if abs(p.x) > tuning.offscreenHorizontalLimit { return false }
        return true
    }

    ///
    /// ⚠️ [待验证] 原版初速/角度的分布规律（是否均匀、是否依赖水果类型、
    ///    是否与 spawner 的 spread 字段相关）均未闭合，此处取「区间内均匀分布」占位。
    public static func launchVelocity(rng: any RandomSource,
                                      tuning: FruitMotionTuning) -> SIMD3<Float> {
        let speed = lerp(tuning.minLaunchSpeed, tuning.maxLaunchSpeed, rng.nextFloat())
        let angle = lerp(tuning.minLaunchAngle, tuning.maxLaunchAngle, rng.nextFloat())
        return SIMD3<Float>(cos(angle) * speed, sin(angle) * speed, 0)
    }

    /// 生成自转角速度。
    /// ⚠️ [待验证] 原版自转轴与分布未知；占位为绕 z 轴、区间均匀。
    public static func initialSpin(rng: any RandomSource,
                                   tuning: FruitMotionTuning) -> SIMD3<Float> {
        let z = lerp(tuning.minSpin, tuning.maxSpin, rng.nextFloat())
        return SIMD3<Float>(0, 0, z)
    }

    // MARK: 内部

    private static func lerp(_ a: Float, _ b: Float, _ t: Float) -> Float {
        a + (b - a) * t
    }

## Kimi 审查时应关注的风险点

1. **`Constants.Physics` 的声明位置（最重要）**：因任务卡只允许 5 个文件，我把 `Physics` 以 `extension Constants` 形式声明在 `FruitMotion.swift`。若后续任何任务卡往 `Constants.swift` 正文加 `Physics`，会**重复声明编译失败**。建议 T-016 把该枚举整体迁入 `Constants.swift` 并删除扩展。
2. **任务卡「改为 import 引用 ECS 模块」无法照字面执行**：FNPBCore 是单 target，`import` 自身模块会编译失败。已改为同模块直接引用并在文件头注明；若未来拆子模块需补 `import FNPBCoreECS`。
3. **`EntityTransform` 新增 `rotation / angularVelocity` 字段**：若已落盘的 Slice/渲染代码用了 memberwise init（`EntityTransform(position:...)` 等）会受影响——我补了一个全参数 `public init`，但**旧的仅 position 写法需要核对**。旋转的轴/角表示仍是 `[待验证]`。
4. **`Entity` 新增 `fruit: FruitInfo?`**：值类型内嵌 Codable struct，实体拷贝体积变大；若渲染层高频拷贝实体需评估。`SliceTesting` 等协议签名未变，既有测试替身应可编译（`init(id:kind:)` 保留）。
5. **抛物线真值全为占位**：重力 -9.8、初速 14~22、角度 60°~120°、自转 ±4 rad/s、离屏阈值 -2/20/40 **全部 `[待验证]`，无任何反编译依据**。尤其「世界单位 vs 屏幕像素」的换算关系未定，手感必然与原版不同，Frida 闭合前不应据此调参下结论。
6. **积分顺序未验证**：半隐式欧拉（先速度后位置）与原引擎是否一致 `[待验证]`；测试只保证实现自洽。若原版是固定步长 1/60 + 显式欧拉，位置轨迹会有半帧偏差。
7. **`forEach` 写回语义**：采用 id 快照 + 写回前重查槽位，body 内 spawn/despawn 是安全的（含触发压缩）；但**body 内不能对同一 store 发起嵌套 forEach 且持有 `inout` 引用**——虽然当前实现用局部拷贝规避了独占性崩溃，语义上仍建议文档化为「禁止重入遍历」。
8. **`forEach(kind:)` 是 O(n) 过滤**（协议扩展默认实现，`any EntityStore` 下静态派发不可被实现类覆盖）。原主循环是三个独立链表循环，语义顺序等价但常数不同；实体数量级 100 内可接受，若未来实体上千需改成分桶（会引入顺序维护成本）。
9. **id 不复用 + `clear` 不重置分配器**：这是我的取舍（保证「id 稳定」），原引擎用的是指针，语义上无 id 概念。若 Kimi 认为 `clear` 后应从 1 重新分配（便于黄金回放对照），需明确。
10. **`EntityStore` 协议面被扩大**（`spawn/despawn/clear/aliveCount/forEach`），GameWorld 未使用新增方法，但任何既有 `EntityStore` 测试替身（如 T-012 的 Slice 测试若用了假 store）**必须补齐新方法**，否则编译失败——风险点需确认其他测试文件是否存在自建 store 替身。
11. **`GameState` 的落盘位置 `[待验证]`**：`GameWorld.swift` 与 `Entity.swift` 都依赖 `GameState`，但本卡注入的只有 `blueprint/GameState.swift`（未确认是否已复制到 `Sources/FNPBCore/`）。若未落盘，全工程编译失败与本卡无关，但会让「Swift 6 可编译」验收无法在 CI 上体现。
12. **`dropState`（原 +0x41 下落态）未在 FruitMotion 中使用**：语义仍是 `[M]` 级，离屏回收只按几何边界判定。若原版实际是「进入下落态才检测回收」，行为会有差异，标注为遗留。
13. **测试框架选择 XCTest**（非 Swift Testing）：与本项目既有黄金值测试保持一致；Swift 6 下 XCTest 有非 Sendable 警告但非错误。若 Kimi 要求 Swift Testing，需整体迁移。
