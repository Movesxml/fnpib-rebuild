## 设计说明

先核对注入文件里**真实存在**的 API，再决定接线方式：

| 需求 | 可用 API | 结论 |
|---|---|---|
| 桥接视图 | `MetalViewRepresentable`（`typealias UIViewType = MetalCanvasView`，`init(metalContext:surface:onDraw:onResize:)`，内部 `bind` 已在 layout/drawableSize 变化时调用 `surface.configure(SurfaceRequest(...))` 并 `surface.attach(view)`） | 直接复用，**不另写桥、不重复 configure**（任务卡第 4 条"桥接内部已处理则复用"成立） |
| 帧入口 | `MetalCanvasView.onDraw: ((MTKView) -> Void)?` | 走 `MetalViewRepresentable(onDraw:)`，即每帧 MTKView draw |
| 相机/尺寸 | `RenderSurface.logicalSize` 在**协议上公开**（`SIMD2<Float>`，逻辑点） | GameRenderer 暴露只读投影，TouchCoordinateMapper 改接它 |
| 渲染提交 | `MetalRenderSurface.beginFrame() -> Bool` / `submit(SpriteBatch)` / `endFrame()` | begin/end 必须严格配对（`beginFrame` 内 `guard currentCommandBuffer == nil`），故用 `defer { endFrame() }` |
| 精灵 | `SpriteInstance(position:size:rotation:uvOrigin:uvSize:tint:)`，**逻辑点、左上原点、y 向下** | 需与"原点中心、y 上"的世界坐标做一次变换 |
| 贴图 | `TextureLoader.load(TextureAsset) throws`；`TextureHandle` 有 public init，可自造 1×1 纯白兜底 | atlas 失败不崩，回落纯色 |

两处**信息缺口必须上报**（见风险清单）：
1. `EntityStore` 的枚举 API 完全没有出现在注入材料里（只见到 `store.clear()` 与 `GameWorld.tick(world:)` 的 inout 用法）→ `GameHost.currentEntities` 只能给空实现 + 精确替换指引，**这一条会挡住"局内有水果"的验收**。
2. `FruitInfo` 的字段名只由任务卡文字给出 `fruit?.typeID`，定义未注入 → 按任务卡原文使用并标 [待验证]。

//
//  GameRenderer.swift
//  App
//
//  T-024：把 FNPBRender 真正挂到 App（蓝图 S7 收口 + S8 最后一公里）。
//
//  数据流（全部主线程）：
//    MetalCanvasView.draw(in:)                ← MTKView 内部 CADisplayLink，120Hz
//      → GameRenderer.drawFrame()
//      → surface.beginFrame()
//      → 读 GameHost.currentState / currentEntities（渲染直读，本卡不做插值）
//      → surface.submit(SpriteBatch) × N
//      → surface.endFrame()                   ← defer 保证配对
//
//  【坐标系】两套约定不一致，本文件只做一次变换（screenPoint(_:logicalSize:)）：
//    世界坐标  = 原点屏幕中心、X 右 Y 上（TouchRouter 注释）
//    SpriteInstance = 逻辑点坐标、左上原点、y 向下（SpriteBatch 注释）
//    ⇒ screenX = W/2 + world.x；screenY = H/2 − world.y
//
//  【[待验证] 集中清单】见文件末尾注释块。
//

import Foundation
import Metal
import SwiftUI
import UIKit
import simd

import FNPBCore
import FNPBRender

@MainActor
final class GameRenderer {

    // MARK: - 依赖

    let metalContext: MetalContext
    let surface: MetalRenderSurface
    let textureLoader: TextureLoader

    /// 渲染数据源。**weak**：GameHost 强持有本对象（`GameHost.renderDriver`），
    /// 本对象反向弱引用宿主，避免保留环。
    weak var host: GameHost?

    // MARK: - 贴图

    /// 唯一已确证图集 `fruit_atlas.png`（T-018）。
    /// UV 子矩形映射未闭合 → v1 整图集拉伸渲染 [待验证]；加载失败保持 nil。
    private var atlas: TextureHandle?

    /// 1×1 纯白兜底纹理：图集缺失时靠 `tint` 画出可辨识方块，不崩。
    private var solidTexture: TextureHandle?

    /// 图集只尝试加载一次（失败也不每帧重试 IO）。
    private var atlasLoadAttempted = false

    // MARK: - 占位常量（全部 [待验证]）

    /// 水果占位边长 / 画面短边。
    /// [待验证] 原版按 15.0 归一化 + `FruitInfo.scale`(默认 25.0) 换算屏幕尺寸，
    /// 世界→逻辑点比例未闭合；闭合后改写为 `transform.scale / 15.0 * 基准长度`。
    private static let fruitSizeRatio: Float = 0.1

    /// 刀光段宽度 / 画面短边。[待验证]
    private static let trailWidthRatio: Float = 0.02

    /// 刀光着色（additive 混合）。[待验证] 原版刀光颜色在特效模块内，未提取。
    private static let trailTint = SIMD4<Float>(0.85, 0.92, 1.0, 1.0)

    // MARK: - 初始化

    init(metalContext: MetalContext) {
        self.metalContext = metalContext
        self.surface = MetalRenderSurface(context: metalContext)
        self.textureLoader = TextureLoader(device: metalContext.device)
        self.solidTexture = Self.makeSolidTexture(device: metalContext.device)
    }

    // MARK: - 视图桥接（复用 FNPBRender，不另写 UIViewRepresentable）

    /// 复用 `MetalViewRepresentable`。
    ///
    /// `MetalViewRepresentable.bind(_:)` 内部已做三件事：
    ///   ① `view.onDraw = onDraw`（帧入口）
    ///   ② `view.onDrawableSizeChange` → `surface.configure(SurfaceRequest(...))`
    ///   ③ `surface.attach(view)`
    /// 因此本文件**不再调用 configure**（任务卡第 4 条「桥接内部已处理则复用」）。
    var canvasView: MetalViewRepresentable {
        MetalViewRepresentable(
            metalContext: metalContext,
            surface: surface,
            onDraw: { [weak self] _ in
                self?.drawFrame()
            },
            onResize: { _, _ in
                // configure 已由 MetalViewRepresentable 内部完成，此处无额外动作。
            }
        )
    }

    /// 渲染层逻辑尺寸（点）。TouchCoordinateMapper 的 logicalSize 数据源。
    var logicalSize: SIMD2<Float> { surface.logicalSize }

    // MARK: - 帧回调

    private func drawFrame() {
        // 【硬约束】beginFrame 与 endFrame 必须严格配对：
        // MetalRenderSurface.beginFrame 在 currentCommandBuffer 非 nil 时永久返回 false，
        // 任何漏掉 endFrame 的早退都会让整条渲染链死锁。
        guard surface.beginFrame() else { return }
        defer { surface.endFrame() }

        guard let host else { return }

        let logicalSize = surface.logicalSize
        guard logicalSize.x > 0, logicalSize.y > 0 else { return }

        loadAtlasIfNeeded()

        guard let texture = atlas ?? solidTexture else { return }

        let state = host.currentState

        submitEntities(texture: texture,
                       entities: host.currentEntities,
                       logicalSize: logicalSize)

        submitSlashTrail(texture: texture,
                         trail: state.slashTrail,
                         logicalSize: logicalSize)
    }

    // MARK: - 贴图

    private func loadAtlasIfNeeded() {
        guard !atlasLoadAttempted else { return }
        atlasLoadAttempted = true

        // [待验证] 资源定位方式：资产管线（tools/AssetPipeline）产出的 PNG 如何进入
        // bundle（ContentBundle / folder reference / 扁平资源）尚未在工程中确认。
        // 这里按「扁平资源名 fruit_atlas.png」尝试，失败则永久回落纯色。
        guard let url = Bundle.main.url(forResource: "fruit_atlas", withExtension: "png") else {
            return
        }

        let asset = TextureAsset(
            id: "fruit_atlas",
            source: .url(url),
            srgb: true,
            generateMipmaps: false,
            premultipliedAlpha: true   // [待验证] PNG 是否预乘
        )
        atlas = try? textureLoader.load(asset)
    }

    private static func makeSolidTexture(device: MTLDevice) -> TextureHandle? {
        let descriptor = MTLTextureDescriptor.texture2DDescriptor(
            pixelFormat: .rgba8Unorm,
            width: 1,
            height: 1,
            mipmapped: false
        )
        descriptor.usage = .shaderRead
        // 需要 CPU 侧 replace(region:) 写入，因此不能是 .private。
        descriptor.storageMode = .shared

        guard let texture = device.makeTexture(descriptor: descriptor) else { return nil }

        var pixel: UInt32 = 0xFFFF_FFFF   // 白，RGBA8
        withUnsafeBytes(of: &pixel) { raw in
            guard let base = raw.baseAddress else { return }
            texture.replace(
                region: MTLRegion(
                    origin: MTLOrigin(x: 0, y: 0, z: 0),
                    size: MTLSize(width: 1, height: 1, depth: 1)
                ),
                mipmapLevel: 0,
                withBytes: base,
                bytesPerRow: 4
            )
        }

        return TextureHandle(texture: texture,
                             assetID: "solid-white",
                             premultipliedAlpha: false)
    }

    // MARK: - 实体精灵

    private func submitEntities(texture: TextureHandle,
                                entities: [Entity],
                                logicalSize: SIMD2<Float>) {
        guard !entities.isEmpty else { return }

        let side = min(logicalSize.x, logicalSize.y) * Self.fruitSizeRatio
        var instances: [SpriteInstance] = []
        instances.reserveCapacity(entities.count)

        for entity in entities {
            guard entity.isVisible else { continue }
            // v1 只画玩家可见的三类实体；slash/jiblet/blast 由特效任务卡负责。
            switch entity.kind {
            case .fruit, .bomb, .coin:
                break
            default:
                continue
            }

            // [待验证] `FruitInfo.typeID` 字段名由任务卡文字给出，定义本轮未注入。
            let typeID = entity.fruit?.typeID ?? Int32(entity.kind.rawValue)

            instances.append(
                SpriteInstance(
                    position: screenPoint(entity.transform.position, logicalSize: logicalSize),
                    size: SIMD2<Float>(side, side),
                    // [待验证] 原引擎水果自转表示未闭合；此处只取欧拉角 z 分量做 2D 旋转。
                    rotation: entity.transform.rotation.z,
                    // [待验证] UV 子矩形未闭合：整图集拉伸（任务卡 v1 允许）。
                    uvOrigin: SIMD2<Float>(0, 0),
                    uvSize: SIMD2<Float>(1, 1),
                    tint: Self.tint(forTypeID: typeID)
                )
            )
        }

        guard !instances.isEmpty else { return }
        surface.submit(SpriteBatch(texture: texture, instances: instances, blend: .alpha))
    }

    // MARK: - 刀光轨迹

    private func submitSlashTrail(texture: TextureHandle,
                                  trail: SlashTrail,
                                  logicalSize: SIMD2<Float>) {
        // 环形缓冲 8 槽，未写入槽为 (0,0,0)：过滤后再按数组序连接相邻点。
        // [待验证] 槽位回绕后数组序 ≠ 时间序，可能出现一次跨环跳线（v1 接受；
        //          原版按 `DAT_005573b4` 槽位指针顺序绘制，闭合后可改为按槽位轮转遍历）。
        let raw = trail.points

        var screenPoints: [SIMD2<Float>] = []
        screenPoints.reserveCapacity(raw.count)
        for point in raw where simd_length_squared(point) > 1e-6 {
            screenPoints.append(screenPoint(point, logicalSize: logicalSize))
        }
        guard screenPoints.count >= 2 else { return }

        let width = min(logicalSize.x, logicalSize.y) * Self.trailWidthRatio
        var instances: [SpriteInstance] = []
        instances.reserveCapacity(screenPoints.count - 1)

        for index in 1..<screenPoints.count {
            let a = screenPoints[index - 1]
            let b = screenPoints[index]
            let delta = b - a
            let length = simd_length(delta)
            guard length > 1e-4 else { continue }

            // 屏幕逻辑坐标（y 向下）里 atan2 得到的就是 SpriteInstance 的正向旋转角，
            // 因为 shader 的旋转与 y 翻转同处一套「逻辑 → NDC」变换内。
            instances.append(
                SpriteInstance(
                    position: (a + b) * 0.5,
                    size: SIMD2<Float>(length, width),
                    rotation: atan2(delta.y, delta.x),
                    tint: Self.trailTint
                )
            )
        }

        guard !instances.isEmpty else { return }
        surface.submit(SpriteBatch(texture: texture, instances: instances, blend: .additive))
    }

    // MARK: - 坐标与颜色

    /// 世界坐标（原点中心、y 上）→ 逻辑点坐标（左上原点、y 向下）。
    ///
    /// [待验证] 依赖「世界单位 == 逻辑点」这一前提。若原版按固定设计分辨率归一化
    /// （`15.0` 除数的语义），此处需要乘一个 world→point 比例，比例值待 Frida 闭合。
    private func screenPoint(_ world: SIMD3<Float>,
                             logicalSize: SIMD2<Float>) -> SIMD2<Float> {
        SIMD2<Float>(logicalSize.x * 0.5 + world.x,
                     logicalSize.y * 0.5 - world.y)
    }

    /// 类型 ID → 占位色。
    /// [待验证] 真实配色在 `fruitlist.xml` 的 colour 字段（T-018 未决项）；
    /// 闭合后改为查表，本函数整体删除。
    private static func tint(forTypeID typeID: Int32) -> SIMD4<Float> {
        var h = UInt32(bitPattern: typeID) &* 2_654_435_761
        h ^= h >> 13
        h = h &* 2_246_822_519

        let r = Float((h >> 0) & 0xFF) / 255.0
        let g = Float((h >> 8) & 0xFF) / 255.0
        let b = Float((h >> 16) & 0xFF) / 255.0

        // 抬底避免接近纯黑（additive/alpha 下不可见）。
        return SIMD4<Float>(0.35 + 0.65 * r,
                            0.35 + 0.65 * g,
                            0.35 + 0.65 * b,
                            1.0)
    }
}

// MARK: - 视图

struct ContentView: View {

    @ObservedObject var host: GameHost

    var body: some View {
        ZStack {
            Color.black.ignoresSafeArea()
            screenContent(viewModel: host.viewModel)
        }
        .onAppear { host.start() }
    }

    /// 顶层路由：只按 `snapshot.phase` 决定挂哪个屏幕。
    @ViewBuilder
    private func screenContent(viewModel vm: AppViewModel) -> some View {
        switch vm.snapshot.phase {

        case .mainMenu:
            MainMenuScreen(snapshot: vm.snapshot, actions: vm.actions)

        case .modeSelect:
            GameModeScreen(snapshot: vm.snapshot, actions: vm.actions)

        case .playing, .paused:
            gameplay(vm: vm)

        case .results:
            ResultsScreen(snapshot: vm.snapshot, actions: vm.actions)
        }
    }

    /// 局内层叠：渲染层 → 触摸层 → HUD →（暂停时）暂停浮层。
    @ViewBuilder
    private func gameplay(vm: AppViewModel) -> some View {
        ZStack {
            // T-024：真实 Metal 渲染层。
            // `MetalContext` 创建失败（无 GPU 环境）时降级回黑屏占位，App 不崩。
            if let renderer = host.renderDriver {
                renderer.canvasView
                    .ignoresSafeArea()
            } else {
                RenderAnchorView()
            }

            // 触摸层仅在真正游玩时挂载：paused 下若仍接收触摸，
            // began 会写入 GameState（slashTrailActive / hitPoint），逻辑态被污染。
            if vm.snapshot.phase == .playing {
                TouchSurfaceView(router: host.touchRouter)
                    .ignoresSafeArea()
            }

            InGameHUDScreen(snapshot: vm.snapshot, actions: vm.actions)

            if vm.snapshot.phase == .paused {
                PauseScreen(snapshot: vm.snapshot, actions: vm.actions)
            }
        }
    }
}

        viewModel.refreshSnapshot()

/// 确定性 PRNG（SplitMix64）。回放一致性要求的 snapshot/restore 直接映射内部状态。
/// [待验证] 原版是 32 位定点随机（§5.3 DAT_005a7930 固定点随机），
/// 序列必然不同；此处只保证「可复现 + 均匀分布」，若需逐帧复刻原版请等 PRNG 任务卡。
final class SplitMix64Random: RandomSource {

    private var state: UInt64

    init(seed: UInt64) {
        self.state = seed == 0 ? 0x9E37_79B9_7F4A_7C15 : seed
    }

    func nextFloat() -> Float {
        // 取高 24 位 → [0, 1)
        Float(next() >> 40) * (1.0 / 16_777_216.0)
    }

    func nextInt(_ upperBound: Int32) -> Int32 {
        guard upperBound > 0 else { return 0 }
        return Int32((next() >> 33) % UInt64(upperBound))
    }

    func snapshot() -> UInt64 { state }

    func restore(_ s: UInt64) { state = s == 0 ? 0x9E37_79B9_7F4A_7C15 : s }

    private func next() -> UInt64 {
        state &+= 0x9E37_79B9_7F4A_7C15
        var z = state
        z = (z ^ (z >> 30)) &* 0xBF58_476D_1CE4_E5B9
        z = (z ^ (z >> 27)) &* 0x94D0_49BB_1331_11EB
        return z ^ (z >> 31)
    }
}

## 审查注意事项（风险点）

**1. `EntityStore` 枚举 API 缺失 —— 阻塞项（最重要）**
`currentEntities` 只能是 `[]`。注入材料里 `EntityStore` 只出现过 `store.clear()` 与 `GameWorld.tick(world:)` 的 inout 用法，没有任何遍历/取值 API。这直接导致**"局内每帧提交水果精灵"验收不达标**（刀光仍能显示，因为走 `state.slashTrail`）。
→ 需要 Kimi 补 `Sources/FNPBCore/ECS/EntityStore.swift` 的真实 API 后再改这一行；我已在属性注释里给出三种候选替换式。

**2. `FruitInfo.typeID` 字段名只来自任务卡文字**
`entity.fruit?.typeID` 是任务卡原文写法，`FruitInfo` 定义（Wave 模块）本轮未注入。若实际字段名是 `id` / `fruitType` 等，`GameRenderer.submitEntities` 会编译失败。
→ 建议 Kimi 顺手确认 `FruitInfo` 定义，或下一轮把该文件放进 `extra_files`。

**3. `TouchCoordinateMapper(logicalSize:)` 的闭包隔离**
把闭包从「无捕获的静态调用」改成「捕获 `renderer` + `MainActor.assumeIsolated`」。若 `TouchCoordinateMapper` 的 `logicalSize` 形参声明为 `@Sendable`，捕获 `GameRenderer`（非 Sendable）会报 Swift 6 并发错误。
→ 需要确认 `TouchCoordinateMapper` 的 init 签名。

**4. `MainActor.assumeIsolated` 的运行时前提**
它假定调用发生在主线程。触摸回调来自 UIKit 事件，必然主线程，成立；但若 `TouchCoordinateMapper` 内部把闭包调度到别处（不知道实现），会触发 `preconditionFailure`。已在注释里写明依据。

**5. `MetalContext()` failable → `renderDriver: GameRenderer?`**
任务卡写的是「GameHost 增 renderDriver 属性」，我给的是 Optional（`MetalContext.init?()` 是 failable）。这是必要的降级路径，`gameplay` 里用 `if let` 分支保留 `RenderAnchorView` 作为兜底。若 Kimi 认为必须是非 Optional，需要在 `GameHost.init` 里用 `fatalError` 或换不可失败的 MetalContext 构造方式。

**6. 坐标系与量纲的三重假设**
- 世界坐标 → 逻辑点：假设 1:1（`screenPoint`）。
- `TouchCoordinateMapper` 的输出基准：原实现喂的是**物理像素**，现在喂**逻辑点**，若 mapper 内部把触摸点归一化到 `[0,1]` 再乘 logicalSize，行为会从"像素坐标"变成"点坐标"——量级差 `screen.scale` 倍。这是任务卡已知项，但**影响切割半径 `sliceRadiusSquared = 225` 的实际命中感受**，不是纯显示问题。
- `SpriteInstance.position` 是「左上原点、y 向下」，我做了一次 center + y 翻转；如果原版世界坐标实际是左上原点，这里会上下颠倒。

**7. 图集资源定位方式未确认**
`Bundle.main.url(forResource: "fruit_atlas", withExtension: "png")` 是猜测。`tools/AssetPipeline` 产出的 264 个 PNG 如何进 bundle（folder reference / 扁平 / ContentBundle 解码）在注入材料里没有。定位失败时只会永远走纯色兜底 —— 不会崩，但看不到美术。

**8. `beginFrame`/`endFrame` 死锁风险已处理**
`MetalRenderSurface.beginFrame` 在 `currentCommandBuffer != nil` 时永久返回 false。我用 `guard beginFrame else { return }` + `defer { endFrame() }` 保证配对。但注意：`MTKView` 的 draw 与 `surface.currentDrawable` 获取在同一主线程，若未来把 `drawFrame` 异步化，配对会失效。

**9. 无渲染插值（60Hz 逻辑 × 120Hz 渲染）**
任务卡允许「渲染层 draw 时直接读 host.currentState」，因此 `renderInterpolationAlpha` 目前未被消费，120Hz 下同一逻辑帧会画两次。若 Kimi 认为 T-024 验收含插值，需要另开卡（`SpriteInstance.position` 需要 `previousTransform`，`Entity` 目前只有一个 `transform`）。

**10. Metal 视图的 `preferredFramesPerSecond = 120` 在 iOS 27 上未验证**
`MetalCanvasView.init` 里写死了 120，`MetalRenderSurface.configure` 又会用 `SurfaceRequest.maxFPS` 回写。两者一致（都来自 `view.preferredFramesPerSecond`），不会震荡；但 ProMotion 120Hz 是否真的生效仍需真机确认（原文件已标 [待验证]）。
