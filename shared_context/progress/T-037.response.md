## 设计说明

**任务性质**：纯草案（staging），不触碰 `Sources/`、`App/`、`ChallengeSelection`、`SplitMix64Random`。

**算法直译（与任务卡逐条对应）**

| 任务卡条目 | 实现 |
|---|---|
| `state = state*0x5d588b656c078965 + 0x269ec3` 按 UInt64 回绕 | `state = state &* M &+ A` |
| 先推进再取 `high32 = UInt32(state >> 32)` | `advance()` 返回 high32，**每次调用（含 bound≤0 分支）都推进一次** |
| `bound==0 / -1` → 返回 high32 的 Int32 位模式 | `Int(Int32(bitPattern: high))` |
| 正 bound → `(UInt64(high32)*UInt64(UInt32(bound)))>>32`，无取模 | 同理，乘积上限 `(2^32-1)^2 < 2^64`，不会溢出 |
| `nextFloat` → `q=(UInt64(high32)*0x7ffff)>>32`，`Float(q)/Float(524287)` | 保持在 Float(binary32) 域内运算，`Float(UInt32)` 对 ≤524287 精确 |
| `snapshot/restore` 精确保存 UInt64（含 0） | `snapshot() -> UInt64` / `restore(_:)`，**不对 0 做任何替换** |
| `public init(seed: UInt64 = 0)` | 原样赋值 |

我用手算复核了任务卡给出的全部 `nextInt` 参考值：seed 0/1/0xdeadbeef 的三个状态对应的 `nextInt(4)`、`nextInt(10)` 逐项吻合（例如 seed0 第二态 high32=0x7188d00c → ×4>>32=1、×10>>32=4；0xdeadbeef 第二态 high32=0xa48f2c2e → 2 与 6），float 位模式量级与阶码也一致（seed0 为 0x3ee3119c ≈ 0.4435，与 1904771084/2^32 相符），故按给定向量落测。

**兼容性提示**：本模块为纯计算代码，无旧 API 依赖；唯一需要注意 Swift 6 下 `Float` 运算在 arm64 上严格为 binary32（不存在 x87 扩展精度问题），与 armv7 原版 VFP 单精度语义一致。

//
//  OriginalRandom.swift
//  FNPBCore
//
//  T-037 草案（仅 staging，未落盘生产目录）
//
//  目的：复刻原版发售版的 64 位 LCG 随机源，供“与原版一致”的回放/校对路径使用。
//  来源：[macho] FUN_00039b24 / FUN_00039a64 / FUN_00062be4 / FUN_00301080
//
//  算法（逐条对齐任务卡，无猜测）：
//    state = state * 0x5d588b656c078965 + 0x0000000000269ec3   （按 2^64 回绕）
//    每次取值：先推进状态，再取 high32 = UInt32(state >> 32)
//    nextInt(b) : b == 0 或 -1  -> Int32 位模式(high32)
//                 b > 0         -> UInt32((UInt64(high32) * UInt64(UInt32(b))) >> 32) 的 Int32 位模式
//    nextFloat(): q = UInt32((UInt64(high32) * 0x7ffff) >> 32)
//                 return Float(q) / Float(524287)          （binary32 语义）
//    snapshot/restore 精确保存 UInt64 state，包括 0（0 种子不做替换）
//
//  约束遵守：
//    - 不替换 App 现有 SplitMix64Random（本类为并行新增实现）
//    - 不修改 ChallengeSelection，不实现特殊组 / 挑战统计
//
//  [待验证] 本草案假设 FNPBCore 中 RandomSource 协议形如：
//    public protocol RandomSource: AnyObject {
//        func nextInt(_ bound: Int) -> Int
//        func nextFloat() -> Float
//    }
//  若实际签名不同（例如 nextInt(bound:) / next(bound:) 或协议额外要求 snapshot），
//  只需调整方法签名与一致性声明，算法体不变。
//

import Foundation

/// 原版游戏的 64 位 LCG 随机源复刻。
///
/// 与 App 现行的 `SplitMix64Random` 并存，不做替换；
/// 供需要逐位对齐原版随机序列的路径（回放、校对、黄金值回归）使用。
///
/// 线程安全：`state` 是可变单一 UInt64，本类以 `@unchecked Sendable` 标记仅为适配
/// Swift 6 并发检查；跨 actor / 跨线程共享时调用方必须自行串行化。
public final class OriginalLCGRandom: RandomSource, @unchecked Sendable {

    // MARK: - 常量（Mach-O 指令立即数 / 数据段）

    /// LCG 乘数 0x5d588b656c078965
    private static let multiplier: UInt64 = 0x5d58_8b65_6c07_8965

    /// LCG 增量 0x0000000000269ec3
    private static let increment: UInt64 = 0x0000_0000_0026_9ec3

    /// 浮点量化乘子/分母 0x7ffff = 524287
    private static let floatQuantizer: UInt32 = 0x0007_ffff

    // MARK: - 状态

    /// 完整 64 位状态。种子 0 原样保留，不做任何替换。
    private var state: UInt64

    // MARK: - 初始化

    /// - Parameter seed: 初始 64 位状态，原样保存（包括 0）。
    public init(seed: UInt64 = 0) {
        self.state = seed
    }

    // MARK: - 核心推进

    /// 推进一次状态并返回 high32。
    ///
    /// 严格遵循“先推进再取”：任何一次取值（含 `nextInt(0)` / `nextInt(-1)`）
    /// 都消耗一次状态推进。
    private func advance() -> UInt32 {
        // &* / &+ 即按 2^64 模回绕
        state = state &* Self.multiplier &+ Self.increment
        return UInt32(truncatingIfNeeded: state >> 32)
    }

    // MARK: - RandomSource

    /// 取 `[0, bound)` 内的随机整数；不使用取模，走 32×32→64 高位缩放。
    ///
    /// - `bound == 0` 或 `bound == -1`：原版语义为“无取值范围”，
    ///   直接返回 high32 的 Int32 位模式（可能为负数）。
    /// - `bound > 0`：返回缩放结果的 Int32 位模式。
    /// - 其它负值：证据中未出现，本草案沿用无界分支（见风险点）。
    public func nextInt(_ bound: Int) -> Int {
        let high = advance()

        guard bound > 0 else {
            // bound == 0 / -1（以及证据未覆盖的其它负值）
            return Int(Int32(bitPattern: high))
        }

        // 证据取 32 位 bound 视图；正常调用范围内 bound <= UInt32.max
        let bound32 = UInt32(truncatingIfNeeded: bound)

        // high <= 2^32-1，bound32 <= 2^32-1，乘积严格 < 2^64，不会溢出
        let scaled = (UInt64(high) * UInt64(bound32)) >> 32
        return Int(Int32(bitPattern: UInt32(truncatingIfNeeded: scaled)))
    }

    /// 取 `[0, 1)` 内的单精度随机浮点数。
    ///
    /// 量化：q = (high32 * 524287) >> 32（q ∈ [0, 524286]），再除以 524287.0f。
    /// 全程 binary32：Float(524287) 可精确表示，q 亦在 Float 的 24 位尾数内精确表示。
    public func nextFloat() -> Float {
        let high = advance()
        // high * 524287 < 2^64，不溢出
        let q = UInt32(truncatingIfNeeded: (UInt64(high) * UInt64(Self.floatQuantizer)) >> 32)
        return Float(q) / Float(Self.floatQuantizer)
    }

    // MARK: - 状态快照

    /// 导出当前的完整 64 位状态（包括 0）。
    public func snapshot() -> UInt64 {
        state
    }

    /// 恢复完整 64 位状态（包括 0）。
    public func restore(_ snapshot: UInt64) {
        state = snapshot
    }
}

//
//  OriginalRandomTests.swift
//  FNPBCoreTests
//
//  T-037 草案（仅 staging，未落盘生产/测试目录）
//
//  参考向量全部来自任务卡给定的 Mach-O 证据序列：
//    - 三个种子（0 / 1 / 0xdeadbeef）各自前三次推进后的 UInt64 状态
//    - 每个状态对应的 nextInt(4) / nextInt(10)
//    - 每个状态对应的 nextFloat() 位模式（binary32）
//
//  [待验证] 若测试 target 名不是 FNPBCoreTests，调整下面的 import。
//

import XCTest
@testable import FNPBCore

final class OriginalLCGRandomTests: XCTestCase {

    // MARK: - 参考向量

    private struct ReferenceVector: Sendable {
        let seed: UInt64
        /// 连续三次推进后的完整 64 位状态
        let states: [UInt64]
        /// 三次独立重放（同种子）调用 nextInt(4) 的结果
        let int4: [Int]
        /// 三次独立重放（同种子）调用 nextInt(10) 的结果
        let int10: [Int]
        /// 三次独立重放（同种子）调用 nextFloat() 的位模式
        let floatBits: [UInt32]
    }

    private static let referenceVectors: [ReferenceVector] = [
        ReferenceVector(
            seed: 0,
            states: [
                0x0000_0000_0026_9ec3,
                0x7188_d00c_55ae_9cb2,
                0x0af5_28d3_a0c3_b2fd
            ],
            int4: [0, 1, 0],
            int10: [0, 4, 0],
            floatBits: [0x0000_0000, 0x3ee3_119c, 0x3d2f_5216]
        ),
        ReferenceVector(
            seed: 1,
            states: [
                0x5d58_8b65_6c2e_2828,
                0xe3b5_43e4_5af1_de8b,
                0x3d7f_ca1a_0b78_ce9a
            ],
            int4: [1, 3, 0],
            int10: [3, 8, 2],
            floatBits: [0x3eba_b0d7, 0x3f63_b53c, 0x3e75_ff1f]
        ),
        ReferenceVector(
            seed: 0xdead_beef,
            states: [
                0x0457_f41a_e269_da0e,
                0xa48f_2c2e_d7fd_2449,
                0x2b33_2719_7970_0090
            ],
            int4: [0, 2, 0],
            int10: [0, 6, 1],
            floatBits: [0x3c8a_fc11, 0x3f24_8f15, 0x3e2c_cc96]
        )
    ]

    // MARK: - 状态序列

    func testStateSequenceMatchesMachOEvidence() {
        for vector in Self.referenceVectors {
            let rng = OriginalLCGRandom(seed: vector.seed)
            var states: [UInt64] = []
            for _ in 0..<vector.states.count {
                _ = rng.nextFloat()          // 任取一次即可推进一次
                states.append(rng.snapshot())
            }
            XCTAssertEqual(
                states,
                vector.states,
                "seed 0x\(String(vector.seed, radix: 16)) 的状态序列不一致"
            )
        }
    }

    // MARK: - nextInt

    func testNextIntBounded() {
        for vector in Self.referenceVectors {
            let four = OriginalLCGRandom(seed: vector.seed)
            let fourResults = (0..<vector.int4.count).map { _ in four.nextInt(4) }
            XCTAssertEqual(
                fourResults,
                vector.int4,
                "seed 0x\(String(vector.seed, radix: 16)) 的 nextInt(4) 序列不一致"
            )

            let ten = OriginalLCGRandom(seed: vector.seed)
            let tenResults = (0..<vector.int10.count).map { _ in ten.nextInt(10) }
            XCTAssertEqual(
                tenResults,
                vector.int10,
                "seed 0x\(String(vector.seed, radix: 16)) 的 nextInt(10) 序列不一致"
            )
        }
    }

    func testNextIntStaysInRange() {
        let rng = OriginalLCGRandom(seed: 0xdead_beef)
        for bound in 1...20 {
            let value = rng.nextInt(bound)
            XCTAssertGreaterThanOrEqual(value, 0, "bound \(bound) 下界越界")
            XCTAssertLessThan(value, bound, "bound \(bound) 上界越界")
        }
    }

    func testUnboundedNextIntReturnsRawBitPattern() {
        // seed 0：第一次推进 state = 0x...269ec3；第二次推进 state = 0x7188d00c55ae9cb2
        // → high32 = 0x7188d00c（正）
        let zeroBound = OriginalLCGRandom(seed: 0)
        _ = zeroBound.nextFloat()
        XCTAssertEqual(zeroBound.nextInt(0), Int(Int32(bitPattern: 0x7188_d00c)))
        XCTAssertEqual(zeroBound.snapshot(), 0x7188_d00c_55ae_9cb2)

        let minusOneBound = OriginalLCGRandom(seed: 0)
        _ = minusOneBound.nextFloat()
        XCTAssertEqual(minusOneBound.nextInt(-1), Int(Int32(bitPattern: 0x7188_d00c)))
        XCTAssertEqual(minusOneBound.snapshot(), 0x7188_d00c_55ae_9cb2)

        // seed 0xdeadbeef：第二次推进 high32 = 0xa48f2c2e → 负值，位模式必须原样保留
        let negative = OriginalLCGRandom(seed: 0xdead_beef)
        _ = negative.nextFloat()
        XCTAssertEqual(negative.nextInt(0), Int(Int32(bitPattern: 0xa48f_2c2e)))
        XCTAssertLessThan(negative.nextInt(0), 0, "高位为 1 时应返回负的 Int32 位模式")
    }

    func testNextIntZeroBoundAdvancesExactlyOnce() {
        let unbounded = OriginalLCGRandom(seed: 0xdead_beef)
        _ = unbounded.nextInt(0)

        let reference = OriginalLCGRandom(seed: 0xdead_beef)
        _ = reference.nextFloat()

        XCTAssertEqual(
            unbounded.snapshot(),
            reference.snapshot(),
            "nextInt(0) 必须只推进一次状态"
        )
    }

    // MARK: - nextFloat

    func testNextFloatBitPatterns() {
        for vector in Self.referenceVectors {
            let rng = OriginalLCGRandom(seed: vector.seed)
            let bits = (0..<vector.floatBits.count).map { _ in rng.nextFloat().bitPattern }
            XCTAssertEqual(
                bits,
                vector.floatBits,
                "seed 0x\(String(vector.seed, radix: 16)) 的 nextFloat 位模式不一致"
            )
        }
    }

    func testNextFloatStaysBelowOne() {
        let rng = OriginalLCGRandom(seed: 0xdead_beef)
        for _ in 0..<1000 {
            let value = rng.nextFloat()
            XCTAssertGreaterThanOrEqual(value, 0)
            XCTAssertLessThan(value, 1)
        }
    }

    // MARK: - 种子与快照

    func testZeroSeedIsPreserved() {
        let defaultSeed = OriginalLCGRandom()
        XCTAssertEqual(defaultSeed.snapshot(), 0, "默认种子必须是 0（不被替换）")

        let explicitZero = OriginalLCGRandom(seed: 0)
        XCTAssertEqual(explicitZero.snapshot(), 0, "显式种子 0 必须原样保存")

        explicitZero.restore(0)
        _ = explicitZero.nextFloat()
        XCTAssertEqual(
            explicitZero.snapshot(),
            0x0000_0000_0026_9ec3,
            "种子 0 的第一步必须得到 0x269ec3（若被替换为其它默认种子会不一致）"
        )
    }

    func testSnapshotRestoreRoundTrips() {
        let rng = OriginalLCGRandom(seed: 1)
        let initial = rng.snapshot()
        XCTAssertEqual(initial, 1)

        var recorded: [(value: Int, state: UInt64)] = []
        for _ in 0..<5 {
            let value = rng.nextInt(7)
            recorded.append((value, rng.snapshot()))
        }

        // 全量重放
        rng.restore(initial)
        for expected in recorded {
            XCTAssertEqual(rng.nextInt(7), expected.value)
            XCTAssertEqual(rng.snapshot(), expected.state)
        }

        // 从中途状态恢复
        rng.restore(recorded[2].state)
        for expected in recorded[3...] {
            XCTAssertEqual(rng.nextInt(7), expected.value)
            XCTAssertEqual(rng.snapshot(), expected.state)
        }
    }

    func testRestoreZeroStateReplaysSeedZero() {
        let rng = OriginalLCGRandom(seed: 0xdead_beef)
        _ = rng.nextFloat()
        _ = rng.nextFloat()

        rng.restore(0)

        let reference = OriginalLCGRandom(seed: 0)
        for _ in 0..<3 {
            XCTAssertEqual(
                rng.nextFloat().bitPattern,
                reference.nextFloat().bitPattern,
                "restore(0) 之后的行为必须与 seed 0 的全新实例逐位一致"
            )
        }
    }
}

## Kimi 审查时应注意的风险点

1. **协议签名是最大不确定项 [待验证]**：草案假设 `RandomSource` 为 `func nextInt(_ bound: Int) -> Int` + `func nextFloat() -> Float` 的 `AnyObject` 协议。T-014/T-015 只提到 `SpawnTable` 用 `RandomSource` 做权重抽取，未见定义原文。若实际是 `nextInt(bound:)`、`nextFloat()`、或协议要求 `snapshot/restore`（则方法签名需并入一致性），需要改签名但不改算法体。请核对 `Sources/FNPBCore` 中 `RandomSource` 真实定义后再落盘。

2. **`nextFloat` 后半段的实现形式 [待验证]**：任务卡写 `Float(q)/Float(524287)`，我按除法实现。原版也可能是 `q * (1.0f/524287.0f)`（乘倒数），两者在个别 q 上有 1 ULP 差异。参考位模式（如 0x3ee3119c）我已核验量级/阶码一致，但未逐一复核全部 9 个向量的最后一位；若 CI 出现 1 ULP 偏差，优先怀疑此处，需回看 `FUN_00062be4` / `FUN_00301080` 的反编译是否含倒数常量（`0x3A000000`≈0.0000019073 等）。

3. **`bound <= 0` 的边界扩展**：任务卡只规定 0 与 -1。草案用 `guard bound > 0 else { ... }` 使**其它负值**也走“返回原始位模式”分支（不崩溃、行为确定）。若认为生产代码不应接受其它负值，建议改为 `precondition(bound >= 0 || bound == -1)`——这是策略选择，不是证据结论，请终审定调。

4. **`bound > UInt32.max` 未定义**：`UInt32(truncatingIfNeeded:)` 会截断，且若 bound > 2^31 结果位模式可能为负。证据中无该路径，建议生产调用点用 `assert` 限制，或在此处加注释/前置条件（当前仅注释标注）。

5. **`@unchecked Sendable` 是有意为之**：Swift 6 strict concurrency 下，若 `RandomSource` 协议本身要求 `Sendable`，不加会编译失败；加了则把串行化责任交给调用方（单 UInt64 状态，非原子）。若协议不要求 `Sendable`，可以删掉以更保守。请确认 `GameWorld` / `TimeDriver` 对随机源的使用是否跨 actor。

6. **证据→函数映射未逐条核对**：任务卡给出 `FUN_00039b24` / `FUN_00039a64` / `FUN_00062be4` / `FUN_00301080` 四个地址，但未说明哪个对应 `nextInt`、哪个对应 `nextFloat`、哪个是播种。草案整体依据任务卡的算法描述实现（该描述内部自洽，且我已手算复核全部 `nextInt` 向量），但若要满足“无猜测”标准，建议 Kimi 在终审时补一条“函数↔API 对应表”到 findings。

7. **未触碰任何生产文件**：未改 `SplitMix64Random`、未动 `App/Info.plist`、未动 `ChallengeSelection`、未实现特殊组或挑战统计，与任务卡约束一致；两个文件均位于 `build/staging/`，落盘路径需要 Kimi 决定（预期 `Sources/FNPBCore/Random/OriginalRandom.swift` 与 `Tests/FNPBCoreTests/OriginalRandomTests.swift`）。

8. **编译验证缺口**：本机为 Windows，无 `swift`/`xcodebuild`，草案未经编译。已知风险点是 `@unchecked Sendable` 的写法在 Swift 6 下的位置（`class Foo: RandomSource, @unchecked Sendable` 合法）与测试 target 名，均需 CI 或 Mac 复核。
