## 原始设计说明

本卡按 `FUN_00053cb8` 末尾循环精确复刻 until 语义，并补全原始字段模型。核心取舍如下：

### until 语义（T-027 修正）
旧实现有两个错误，本卡一次性纠正：

1. **显式有效的 until 被吞掉**：旧 step3 会把 `until=5`、`后续 waveNo=2` 改写为 `1`。原版 `FUN_00053cb8` 末尾循环只处理**未解析（-1）的条目**，显式有效的 `until` 一律保留。
2. **waveNo 使用数组下标兜底**：旧实现 `Int32(j + 1)` 强制 1 基。真实文件 `waveNo` 从 0 开始且允许重复，必须按原始值比较。

新流程：
```
1. forever → -2
2. atoi(token) 且 >= waveNo[i] → 采纳为显式有效；否则保留 -1
3. 对仍为 -1 的条目：
   a. 先设 -2
   b. 从所有 waveNo[j] > waveNo[i] 中取 min，找到则覆盖为 min - 1
   c. 否则保持 -2（forever）
4. 显式有效条目绝不改写
```

### 字段模型补全（不改变调度器）
- **WaveInfo**：新增 `waveNo: Int32 = -1`（原始波次编号，可比 -1 表示未赋值）、`chance: Float = 0`（原始 chance 属性，与 `chanceRegrowth` 语义关系待 T-028 JSON 加载器闭合，不臆造映射）。
- **Spawner**：新增 `min` / `max` / `minInc` / `maxInc` / `delay` / `delayInc` 六个原始字段（不可继续用 `minWait/maxWait` 冒充），默认 0 保证既有默认值不变。`minWait/maxWait` 保留不删——本卡不改调度器，WaveDirector 仍复用。

### 兼容性风险
- **API 破坏**：`postProcessUntil` 参数名 `waveNumbers` → `waveNos`；`applyUntilPostProcess` 参数从 `waveNumbers: [Int32]` → `rawTokens: [String]`。前者强制调用方改用真实 `waveNo`，后者是因为旧实现用 `String($0.until)` 反推 token 本身有损（无法还原 `forever`），必须由调用方持有原始 token。[待验证] 项目内是否有其他文件调用这两个方法（本卡无法跨文件确认，若 CI 报未解析符号需 Kimi 在终审时补 `[待验证]` 清单）。
- **`precondition` 而非静默截断**：`waveNos.count != rawTokens.count` 时崩溃而非兜底，防止错误下标语义回流。若调用方发现该断言触发，属调用方 bug。

### 测试覆盖
- 更新 `test_WaveInfo_defaults` / `test_Spawner_defaults` 覆盖新字段。
- 重写全部 until 测试用 `waveNos`（真实 0 基）。
- 新增 4 组核心用例：显式有效不变、缺省取最近后续-1、无后续为 -2、重复 waveNo 跳过。
- 补充 "所有严格更大（含前面索引）" 用 `[2,0,3]` 验证不是仅"后续索引"。

public extension WaveInfo {

    /// `until` 语义后处理（core_logic_notes §4.4 + T-027 精修；
    /// **[macho] 独有**，exe 未见；精确符合 `FUN_00053cb8` 末尾循环）。
    ///
    /// 规则（按序执行，顺序不可交换）：
    ///  1. `"forever"`（大小写不敏感）→ `-2`（`Constants.WaveDefaults.untilForever`）
    ///  2. `atoi(token)` 得到数值 `v`，仅当 `v >= waveNo[i]` 时采纳为「显式且有效」
    ///  3. 仅对**仍为 -1**（未解析 / 未采纳）的条目：
    ///     a. 先设为 `-2`（forever 兜底）
    ///     b. 从**所有** `waveNo[j] > waveNo[i]` 中取最小 `waveNo`，找到则覆盖为 `min - 1`
    ///     c. 若无严格更大的 waveNo（当前是最大 / 全部重复），保持 `-2`
    ///  4. **显式有效的 `until` 绝不做旧 step3 改写**（T-027 修正）：
    ///     旧实现会把「显式 5、后续 waveNo=2」改写成 1，与原版不符
    ///
    /// 例：
    /// ```
    /// rawTokens=["garbage","forever"], waveNos=[0,3]
    ///   i=0: 未解析 → -2 → 所有 >0 中最小=3 → 3-1=2
    ///   i=1: forever → -2
    /// result = [2,-2]
    ///
    /// rawTokens=["5","forever"], waveNos=[0,2]
    ///   i=0: "5">=0 → 显式有效 5（不因后续 waveNo=2 而改写）
    ///   i=1: forever → -2
    /// result = [5,-2]
    /// ```
    ///
    /// 说明：真实文件 `waveNo` 从 0 起且允许重复；`waveNos` 必须与 `rawTokens` 一一对应，
    ///       禁止用数组下标 +1 兜底（任务卡硬约束）。
    ///
    /// - Parameters:
    ///   - rawTokens: XML `until` 原始串数组（顺序即波次写入顺序）
    ///   - waveNos:   每波原始 `waveNo`（严格与 rawTokens 等长；可重复）
    /// - Returns: 与 `rawTokens` 等长的后处理结果
    static func postProcessUntil(rawTokens: [String], waveNos: [Int32]) -> [Int32] {
        let n = rawTokens.count
        guard n > 0 else { return [] }
        precondition(waveNos.count == n,
                     "postProcessUntil: waveNos 必须与 rawTokens 等长（禁止下标兜底）")

        // 步骤 1/2：forever → -2；atoi 且 >= waveNo → 采纳为显式有效；否则保留 -1
        var result = [Int32](repeating: Constants.WaveDefaults.untilUnparsed, count: n)
        for i in 0..<n {
            let token = rawTokens[i].trimmingCharacters(in: .whitespaces)
            if token.lowercased() == "forever" {
                result[i] = Constants.WaveDefaults.untilForever
                continue
            }
            guard let parsed = Int32(token) else { continue }
            if parsed >= waveNos[i] {
                result[i] = parsed
            }
        }

        // 步骤 3（T-027 新语义）：未解析(-1) 条目先 -2，再最近后续 waveNo - 1 覆盖
        for i in 0..<n where result[i] == Constants.WaveDefaults.untilUnparsed {
            result[i] = Constants.WaveDefaults.untilForever

            let currentNo = waveNos[i]
            var minGreater: Int32? = nil
            for j in 0..<n where j != i {
                let wj = waveNos[j]
                // 严格大于；重复 waveNo 自动跳过（原版 FUN_00053cb8 末尾循环语义）
                guard wj > currentNo else { continue }
                if minGreater == nil || wj < minGreater! {
                    minGreater = wj
                }
            }
            if let g = minGreater {
                result[i] = g - 1
            }
            // else：无严格更大波次 → 保持 -2（forever）
        }

        return result
    }

    /// 就地应用后处理结果（辅助入口）。
    ///
    /// - Parameters:
    ///   - waves:     待后处理的 WaveInfo 数组（要求每项 `waveNo >= 0` 已由解析层填好）
    ///   - rawTokens: XML `until` 原始串数组（与 `waves` 顺序一致）
    ///
    /// ⚠️ 本 API 不再用 `String($0.until)` 反推 token —— Int32 → String 会丢失原始字面量
    ///    （如 `forever` / 前导空串），必须由调用方持有原始串。
    static func applyUntilPostProcess(to waves: inout [WaveInfo], rawTokens: [String]) {
        let waveNos = waves.map { $0.waveNo }
        let processed = postProcessUntil(rawTokens: rawTokens, waveNos: waveNos)
        for i in 0..<min(waves.count, processed.count) {
            waves[i].until = processed[i]
        }
    }
}

/// 确定性 LCG 随机源，固定种子即可复现分布。
/// 与 `FNPBCore.RandomSource` 协议一致。
final class SeededRandomSource: RandomSource {

    private var state: UInt64

    init(seed: UInt64 = 1) {
        // 避免 0 态锁死
        self.state = seed == 0 ? 1 : seed
    }

    func nextFloat() -> Float {
        // Numerical Recipes LCG（64 位实现）
        state = state &* 6364136223846793005 &+ 1442695040888963407
        // 取高 32 位并规约到 [0,1)
        let bits = UInt32(truncatingIfNeeded: state >> 32)
        return Float(bits) / (Float(UInt32.max) + 1.0)
    }

    func nextInt(_ upperBound: Int32) -> Int32 {
        guard upperBound > 0 else { return 0 }
        let v = Int32(nextFloat() * Float(upperBound))
        // 防御性截断（浮点误差理论上可产生 == upperBound）
        return min(max(v, 0), upperBound - 1)
    }

    func snapshot() -> UInt64 { state }
    func restore(_ s: UInt64) { state = s == 0 ? 1 : s }
}

1. **API 破坏（跨文件）**：`WaveInfo.postProcessUntil(rawTokens:waveNumbers:)` → `postProcessUntil(rawTokens:waveNos:)`；`applyUntilPostProcess(to:waveNumbers:)` → `(to:rawTokens:)`。**本卡只改两个文件**，未验证项目内是否有其他文件调用这两个方法（如 T-028 计划中的 JSON 加载器若已先行落地则会冲突）。若 CI 报未解析符号，属跨文件协调问题，非本卡逻辑缺陷。

2. **`applyUntilPostProcess` 语义变更**：旧实现用 `String($0.until)` 反推 token（有损：`forever` 与 `-2` 无法区分，`" 5"` 前导空格丢失）。新签名强制由调用方持有原始 token。请确认 T-028 加载器设计时已接受此约束。

3. **`precondition` 采取崩溃而非静默策略**：若 `waveNos.count != rawTokens.count` 会崩溃。这是防止旧下标兜底语义回流的防线，但也意味着解析层必须严格对齐。若解析层有"allowMissing"需求，需在 T-028 显式增加 `waveNos` 不足时的补齐策略卡片。
