## 设计说明

**改动范围（3 处生产语义 + 1 组测试，全部落在 `build/staging/T-043/`）**

| 位置 | 改动 |
|---|---|
| 新增 `SpecialChallengeGroup.swift` | 特殊组模型：`numPerGame` / `challengeGroup` / `selectedCount` / 独立 `ChallengeGroupSelector`；门控 + 阈值 + **唯一一次 RNG 消耗**全部收敛到 `tryConsume(difficulty:tierIndex:rng:)` 一个函数 |
| `ChallengeCatalog` | 新增 `specialChallenges: SpecialChallengeGroup?`，缺省 `nil`（JSON 无该键 → nil → **零 RNG**）；`loadSpecialChallenges(numPerGame:challengeGroup:)` 按 `groups` 表解析，组不存在则保持 `nil`（不虚构挑战）；`resetSpecialChallengeCounterForNewGame()` |
| `ChallengeSelection` | 在「必选队列构建之后 / 成对洗牌之前」插入特殊组门控一段；命中则 `append` 到必选队列并透出 `specialPicked`；`mustSelect`、成对洗牌、队列填充三步顺序未动；修正过时注释 |
| 测试 | 用「RNG 副本重放比对」测消耗次数（无需改生产 RNG 类型）：无特殊组/numPerGame=0/tierIndex∈{0,2}/count>0 → **0 次**；进入门控 → **恰好 1 次**；阈值 0.2/0.5/0.8/0.8 用实际 roll 反推期望，避免硬编码种子 |

**关键设计取舍**

1. `difficulty`、`tierIndex` 一律显式入参，无默认值、无全局、无推导——满足「不得虚构难度值」。
2. 特殊组的 `selectedCount` 变更后回写 `catalog.specialChallenges`（`ChallengeCatalog` 是 struct），避免值语义丢失。
3. `ChallengeGroupSelector` 的组内选取**不消耗 `OriginalLCGRandom`**（门控之外的 RNG 消耗无证据支持），以单行 `[MERGE]` 标记，便于 Kimi 对齐生产版实现。
4. 全部门控早退判断放在 `roll` 之前，保证「不满足条件时零消耗」。

> ⚠️ 重要前提：任务卡引用的 4 份证据文件（`special_challenge_group_macho.md`、`special_challenge_reset_macho.md`、`challenge_tier_layout_macho.md`、`challenge_selection_weights_macho.md`）**未注入到我的上下文**（findings 里只有 binary_equivalence / bomb_spawn_constants / challenge_ac24_predicate / challenge_bonus_mods / challenge_condition_concrete / challenge_condition_exact_vtables）。因此实现严格按任务卡文字规格写，两处文字未覆盖的细节（**阈值比较方向**、**特殊项入队位置**）已标注 `[待验证]`，请 Kimi 用那 4 份文件核对后再落盘。

import Foundation

/// 挑战组内选择器（原版：按 challengeGroup 归组后取候选）
///
/// [MERGE] 若生产版已存在同名类型，删除本定义，仅保留 `selectNext()` 调用点。
/// 本实现**不消耗** `OriginalLCGRandom`：任务卡只授权门控处的一次 RNG 消耗，
/// 组内选取的额外随机性无证据支持，不得自行加入。
public struct ChallengeGroupSelector: Sendable, Equatable {

    /// 组名（对应 challenges 表中的 group 字段）
    public let group: String

    /// 该组候选挑战索引（顺序即原版表顺序，由 ChallengeCatalog.groups 提供）
    public let candidates: [Int]

    /// 轮转游标
    private var cursor: Int

    public init(group: String, candidates: [Int], cursor: Int = 0) {
        self.group = group
        self.candidates = candidates
        self.cursor = candidates.isEmpty ? 0 : cursor % candidates.count
    }

    public var isEmpty: Bool { candidates.isEmpty }

    /// 组内取下一个挑战索引（顺序轮转，不重复直到走完一轮）。
    ///
    /// [MERGE] 若生产版组内选取为其它策略，替换本函数体即可；
    /// 但**不得**改用 `OriginalLCGRandom` —— 会破坏「特殊组只多消耗 1 次 RNG」的验收口径。
    public mutating func selectNext() -> Int? {
        guard !candidates.isEmpty else { return nil }
        let value = candidates[cursor]
        cursor = (cursor + 1) % candidates.count
        return value
    }
}

/// 特殊挑战组（原版 challenges 表可选的 specialChallenges 条目）
///
/// 真实 `ch1challengeList.json` 无 `specialChallenges` 字段 →
/// `ChallengeCatalog.specialChallenges == nil` → 整段逻辑短路，**零 RNG 消耗**。
public struct SpecialChallengeGroup: Sendable, Equatable {

    /// 每局投放数量（原版 `numPerGame`）。0 = 关闭
    public let numPerGame: Int

    /// 组名（原版 `challengeGroup`）
    public let challengeGroup: String

    /// 本局已选计数（新局由 `resetForNewGame()` 清零）
    public private(set) var selectedCount: Int

    /// 本组独立的组内选择器（不与其它组共享游标）
    public private(set) var selector: ChallengeGroupSelector

    public init(numPerGame: Int,
                challengeGroup: String,
                selector: ChallengeGroupSelector,
                selectedCount: Int = 0) {
        self.numPerGame = numPerGame
        self.challengeGroup = challengeGroup
        self.selector = selector
        self.selectedCount = selectedCount
    }

    /// 新局清零。
    ///
    /// 注意：只清 `selectedCount`；`selector` 的轮转游标**不**回卷（任务卡只要求计数清零，
    /// 游标是否随新局重置未见证据，见 README 风险点 R4）。
    public mutating func resetForNewGame() {
        selectedCount = 0
    }

    /// 难度 → 投放阈值。
    ///
    /// 0 → 0.2 / 1 → 0.5 / 2 → 0.8 / 其他 → 0.8（与任务卡给定表逐项一致）。
    public static func spawnThreshold(difficulty: Int) -> Float {
        switch difficulty {
        case 0: return 0.2
        case 1: return 0.5
        case 2: return 0.8
        default: return 0.8
        }
    }

    /// 本局特殊挑战投放判定（门控 + 阈值 + 组内选择）。
    ///
    /// 门控顺序严格按要求：
    ///   `numPerGame != 0` → `selectedCount == 0` → `tierIndex != 0 && tierIndex != 2`
    /// 全部门控通过后才消耗**一次** `OriginalLCGRandom.nextFloat()`。
    ///
    /// - Returns: 命中的挑战索引（同时 `selectedCount += 1`）；未命中返回 nil。
    public mutating func tryConsume(difficulty: Int,
                                    tierIndex: Int,
                                    rng: inout OriginalLCGRandom) -> Int? {
        // 门控 1：numPerGame != 0（0 表示该组关闭）
        guard numPerGame != 0 else { return nil }

        // 门控 2：本局尚未选过
        guard selectedCount == 0 else { return nil }

        // 门控 3：tierIndex 0 / 2 不放特殊挑战
        guard tierIndex != 0, tierIndex != 2 else { return nil }

        // —— 唯一一次 RNG 消耗 ——
        let roll = rng.nextFloat()

        // [待验证] 比较方向：现按 roll < threshold（难度越高越容易命中）。
        // 需与 FUN_00060d04 / FUN_00062be4 的分支指令逐条核对。
        guard roll < Self.spawnThreshold(difficulty: difficulty) else { return nil }

        selectedCount += 1

        // 组内选择；组为空（数据异常）时返回 nil，但计数已加，避免重复消耗 RNG
        return selector.selectNext()
    }
}

import Foundation

/// 挑战清单（原版 `challenges/ch1challengeList.json` 解码产物）
///
/// 本文件为 T-043 舞台草稿：**仅 `specialChallenges` 相关为新增**，
/// `entries` / `mustSelect` / `groups` / 填充辅助等既有部分按任务卡描述还原，
/// 落盘时请以生产文件为底做最小合并（勿整体覆盖）。
public struct ChallengeCatalog: Sendable {

    /// 单条挑战定义
    public struct Entry: Sendable, Equatable {
        /// 挑战索引（队列元素即此值）
        public let index: Int
        /// 所属组名（用于 ChallengeGroupSelector 候选表）
        public let group: String?
        /// 挑战自身难度（0/1/2/其他），与特殊组阈值表对应
        public let difficulty: Int

        public init(index: Int, group: String? = nil, difficulty: Int = 0) {
            self.index = index
            self.group = group
            self.difficulty = difficulty
        }
    }

    /// 全部挑战
    public var entries: [Entry]

    /// 必选挑战（进队列前先入 mustSelect）
    public var mustSelect: [Int]

    /// 组名 → 候选挑战索引（顺序即原版表顺序）
    public var groups: [String: [Int]]

    /// 特殊挑战组。
    ///
    /// - 真实 `ch1challengeList.json` 无 `specialChallenges` 字段 → **恒为 nil**；
    /// - 为 nil 时 `ChallengeSelection` 整段短路，**零 RNG 消耗**；
    /// - 不得凭空调用 `loadSpecialChallenges` 造出组。
    public var specialChallenges: SpecialChallengeGroup?

    public init(entries: [Entry] = [],
                mustSelect: [Int] = [],
                groups: [String: [Int]] = [:],
                specialChallenges: SpecialChallengeGroup? = nil) {
        self.entries = entries
        self.mustSelect = mustSelect
        self.groups = groups
        self.specialChallenges = specialChallenges
    }

    /// 组名 → 候选索引（带默认空表）
    public func candidates(forGroup group: String) -> [Int] {
        groups[group] ?? []
    }

    /// 加载特殊挑战组（唯一的构造入口）。
    ///
    /// - `numPerGame == 0`：仍建组，交由 `tryConsume` 的门控 1 关闭（保证 RNG 账不受加载时机影响）。
    /// - 组名在 `groups` 中不存在或候选为空：**保持 nil**，绝不虚构特殊挑战。
    public mutating func loadSpecialChallenges(numPerGame: Int, challengeGroup: String) {
        let candidates = candidates(forGroup: challengeGroup)
        guard !candidates.isEmpty else {
            specialChallenges = nil
            return
        }
        specialChallenges = SpecialChallengeGroup(
            numPerGame: numPerGame,
            challengeGroup: challengeGroup,
            selector: ChallengeGroupSelector(group: challengeGroup, candidates: candidates)
        )
    }

    /// 移除特殊挑战组（回到「无特殊组」状态，零 RNG）
    public mutating func clearSpecialChallenges() {
        specialChallenges = nil
    }

    /// 新局开始：特殊组已选计数清零。
    public mutating func resetSpecialChallengeCounterForNewGame() {
        specialChallenges?.resetForNewGame()
    }
}

import Foundation

/// 挑战选择：把「必选 + 特殊组 + 成对洗牌 + 填充」编成每局队列。
///
/// 随机源为**原版同源** `OriginalLCGRandom`（原版 LCG，参数与步进已在 T-007 逐常量闭合），
/// 不是通用 RNG —— 早前注释「随机源非原版」作废。
///
/// 本文件为 T-043 舞台草稿：`// —— T-043 ——` 标记块为新增，
/// 其余（mustSelect 构建 / 成对洗牌 / 队列填充）按现有行为还原，落盘时以生产文件为底合并。
public enum ChallengeSelection {

    /// 一局的选择结果
    public struct Plan: Sendable, Equatable {
        /// 本局挑战索引队列（长度 = slotCount，池不足时可能偏短）
        public var queue: [Int]
        /// 本局命中的特殊挑战索引（nil = 未命中或未启用）
        public var specialPicked: Int?

        public init(queue: [Int], specialPicked: Int? = nil) {
            self.queue = queue
            self.specialPicked = specialPicked
        }
    }

    /// 生成一局队列。
    ///
    /// - Parameters:
    ///   - catalog: 挑战清单；`specialChallenges` 非 nil 时其 `selectedCount` 会被就地更新
    ///   - slotCount: 本局槽位数
    ///   - difficulty: 难度（显式注入，决定特殊组阈值 0.2/0.5/0.8/0.8）
    ///   - tierIndex: 层级索引（显式注入；0 / 2 不放特殊挑战）
    ///   - rng: 原版 LCG（原样传入传出，消耗次数见 README §3）
    public static func makePlan(catalog: inout ChallengeCatalog,
                                slotCount: Int,
                                difficulty: Int,
                                tierIndex: Int,
                                rng: inout OriginalLCGRandom) -> Plan {

        // 步骤 1（现有）：必选队列
        var mustSelect: [Int] = catalog.mustSelect
        var specialPicked: Int? = nil

        // —— T-043 —— 特殊挑战组：门控通过前零 RNG，命中后追加到必选队列
        if var group = catalog.specialChallenges {
            let picked = group.tryConsume(difficulty: difficulty,
                                          tierIndex: tierIndex,
                                          rng: &rng)
            // 值语义回写：selectedCount / selector 游标必须留存
            catalog.specialChallenges = group
            if let picked {
                mustSelect.append(picked)
                specialPicked = picked
            }
        }
        // —— T-043 结束 ——

        // 步骤 2（现有）：成对洗牌
        shuffleInPairs(&mustSelect, rng: &rng)

        // 步骤 3（现有）：填充到 slotCount（按表顺序跳过已选项）
        var queue = mustSelect
        var used = Set(queue)
        let pool = catalog.entries.map { $0.index }
        var cursor = 0
        while queue.count < slotCount && cursor < pool.count {
            let candidate = pool[cursor]
            cursor += 1
            guard !used.contains(candidate) else { continue }
            queue.append(candidate)
            used.insert(candidate)
        }

        return Plan(queue: queue, specialPicked: specialPicked)
    }

    /// 成对洗牌（现有行为，未改动）。
    ///
    /// [待验证] 每对是否消耗一次 `nextFloat` 依生产实现为准；本函数仅为让草稿自洽而还原形态。
    static func shuffleInPairs(_ list: inout [Int], rng: inout OriginalLCGRandom) {
        guard list.count > 1 else { return }
        var i = 0
        while i + 1 < list.count {
            let roll = rng.nextFloat()
            if roll < 0.5 { list.swapAt(i, i + 1) }
            i += 2
        }
    }
}

import XCTest
@testable import FNPBCore

/// T-043：特殊挑战组与回合计划
///
/// 验收口径：概率 / 门控 / 顺序 / RNG 次数逐项对应 Mach-O；
/// 无特殊组时零额外 RNG。
///
/// RNG 消耗次数用「副本重放比对」测量，不依赖 OriginalLCGRandom 的内部 state 可见性。
final class ChallengeSpecialGroupTests: XCTestCase {

    // MARK: - 夹具

    /// [MERGE] 若 OriginalLCGRandom 的初始化器签名不同，只改这一处
    private func seedRNG(_ seed: UInt32) -> OriginalLCGRandom {
        OriginalLCGRandom(seed: seed)
    }

    private func makeGroup(numPerGame: Int = 1,
                           challengeGroup: String = "special_a",
                           candidates: [Int] = [100, 101, 102]) -> SpecialChallengeGroup {
        SpecialChallengeGroup(numPerGame: numPerGame,
                              challengeGroup: challengeGroup,
                              selector: ChallengeGroupSelector(group: challengeGroup,
                                                               candidates: candidates))
    }

    private func makeCatalog(special: (numPerGame: Int, group: String)? = nil) -> ChallengeCatalog {
        var catalog = ChallengeCatalog(
            entries: (0..<8).map { ChallengeCatalog.Entry(index: $0, group: "g", difficulty: 1) },
            mustSelect: [10, 11],
            groups: ["special_a": [100, 101, 102], "empty_group": []],
            specialChallenges: nil
        )
        if let special {
            catalog.loadSpecialChallenges(numPerGame: special.numPerGame,
                                          challengeGroup: special.group)
        }
        return catalog
    }

    // MARK: - RNG 消耗测量

    private func sample(_ rng: OriginalLCGRandom, count: Int = 3) -> [Float] {
        var copy = rng
        var out: [Float] = []
        for _ in 0..<count { out.append(copy.nextFloat()) }
        return out
    }

    /// 从 seed 起步，走到与 rng 相同状态需要多少次 nextFloat()
    private func consumed(_ rng: OriginalLCGRandom, from seed: UInt32, limit: Int = 256) -> Int? {
        let target = sample(rng)
        for k in 0...limit {
            let probe = seedRNG(seed)
            var advanced = probe
            for _ in 0..<k { _ = advanced.nextFloat() }
            if sample(advanced) == target { return k }
        }
        return nil
    }

    private func rngCount(after body: (inout OriginalLCGRandom) -> Void, seed: UInt32) -> Int? {

    func testGateConsumesExactlyOneRNGAndThresholdGovernsOutcome() {
        let cases: [(difficulty: Int, threshold: Float)] = [(0, 0.2), (1, 0.5), (2, 0.8), (9, 0.8)]
        for item in cases {
            var hits = 0
            for seed in UInt32(1)...UInt32(40) {
                // 先用副本读出本次 roll，据此反推期望，避免硬编码种子
                var probe = seedRNG(seed)

                var rng = seedRNG(seed)
                var group = makeGroup(numPerGame: 1)
                let picked = group.tryConsume(difficulty: item.difficulty, tierIndex: 1, rng: &rng)

                if roll < item.threshold {
                    hits += 1
                    XCTAssertNotNil(picked, "difficulty=\(item.difficulty) seed=\(seed) 应命中")
                    XCTAssertEqual(group.selectedCount, 1)
                } else {
                    XCTAssertNil(picked, "difficulty=\(item.difficulty) seed=\(seed) 不应命中")
                    XCTAssertEqual(group.selectedCount, 0)
                }
                XCTAssertEqual(consumed(rng, from: seed), 1,
                               "difficulty=\(item.difficulty) seed=\(seed) 命中与否都必须恰好消耗 1 次")
            }
            XCTAssertGreaterThan(hits, 0, "difficulty=\(item.difficulty) 样本应至少覆盖一次命中")
        }
    }

## 风险点（请 Kimi 审查时逐条核对）

**R1 — `count == 0` 与 `numPerGame > 1` 语义冲突（高）**
任务卡字面写「`count == 0` 时消费一次」，则 `numPerGame` 只起开关作用（>1 与 1 等价，每局最多 1 个）。若 Mach-O 实为 `count < numPerGame`，则多数量场景行为会整体偏差。请用 `special_challenge_group_macho.md` 对齐后决定；代码只改一行。

**R2 — 特殊项入队位置影响成对洗牌的 RNG 账（高）**
我按「mustSelect 构建后、成对洗牌前」插入。若洗牌每对消耗一次 RNG（现状假定如此），则**多一个入队元素 → 多一对 → 洗牌 RNG +1**。这会让「特殊组只多消耗 1 次 RNG」的总量口径变成 +2。请核对 `FUN_0006ee88` 相对 `FUN_0005fc1c` 中洗牌/填充的调用时序：若原版是「洗牌后追加」，则特殊项不进洗牌、总量才是严格 +1。

**R3 — 阈值比较方向为 `[待验证]`**
现写 `roll < threshold`（难度越高越易命中，与 0.2/0.5/0.8 单调递增自洽）。仍需 `FUN_00060d04` / `FUN_00062be4` 的分支指令确认；若是 `>` 或 `<=`，改一行即可，测试中的期望由实际 roll 反推，会自动跟随。

**R4 — `resetForNewGame()` 只清计数、不回卷 selector 游标**
任务卡只要求计数清零。若原版新局也重置组内游标（或干脆每局重建 selector），轮转序列会不同。`testSelectorRotatesAcrossGamesAndDoesNotTapLCG` 已断言「跨局轮转」，若原版是「每局从组首开始」，该用例需改为 `XCTAssertEqual(first, next)`。

**R5 — 4 份关键证据文件未注入我的上下文**
`special_challenge_group_macho.md`、`special_challenge_reset_macho.md`、`challenge_tier_layout_macho.md`、`challenge_selection_weights_macho.md` 均不在本次 findings 注入列表中（注入的是 binary_equivalence、bomb_spawn_constants、challenge_ac24_predicate、challenge_bonus_mods、challenge_condition_concrete、challenge_condition_exact_vtables）。本实现严格照任务卡文字规格，**除任务卡已给的 0.2/0.5/0.8 与 tierIndex 0/2 外未引入任何新数值**；若有遗漏分支（如 `tierIndex == 1` 之外还有其它放行档），需要那些文件才能补。

**R6 — 生产文件形态未知，草稿的"既有部分"是还原而非原文**
`entries` / `groups` / `mustSelect` / `shuffleInPairs` / 填充循环按任务卡描述还原，仅为让草稿自洽可测。**落盘必须合并而非覆盖**，否则会静默丢失生产版既有逻辑（与 D-T020-plist-single-source 同类事故）。

**R7 — `OriginalLCGRandom(seed: UInt32)` 与 `nextFloat()` 签名是假定值**
测试的消耗测量走「副本重放比对」不依赖内部 state，但初始化器名不同会编译失败；已集中到 `seedRNG(_:)` 一处。

**R8 — 命中但组为空时 `selectedCount` 仍 +1**
`tryConsume` 中先 `selectedCount += 1` 再 `selector.selectNext()`。若组表在加载后被清空（理论不会发生，`loadSpecialChallenges` 已拒绝空组），会出现「计数消耗但无挑战入队」。若原版是「取到才计数」，需要调整顺序。

**R9 — `numPerGame == 0` 仍建组**
我让 `loadSpecialChallenges` 在 `numPerGame == 0` 时仍建组，由门控 1 关闭，以让「RNG 账与加载时机解耦」（便于单测）。若原版在加载期就丢弃，行为等价（都零 RNG），但 `catalog.specialChallenges` 是否为 nil 的可观测差异存在——若 UI 层读该字段，需确认。

**R10 — iOS 27 侧无关但需知会**
本任务纯 Swift 逻辑（无 UIKit/OpenGL/UIWebView/32 位依赖），无平台兼容性风险；`Sendable` 标注在 Swift 6 strict concurrency 下要求 `OriginalLCGRandom` 也满足 `Sendable`（值类型 + 无可变引用通常自动满足），若生产版未标注会编译报错。
