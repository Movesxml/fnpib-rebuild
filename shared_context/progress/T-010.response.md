## 2. 运行时分层与帧时序

```
CADisplayLink(120Hz) → DisplayLinkDriver ── FrameStamp(dt) ──┐
                                                             ▼
                     FixedStepDriver(1/60, maxSubsteps 4) → GameTicking.tick(dt)
                                                             │
        ┌────────────────────────────┬───────────────────────┼──────────────┐
        ▼                            ▼                       ▼              ▼
  WaveDirector.tick          SliceTesting 判定          ComboTracker     ScoreEventBus
  (生成/冻结/炸弹)            (每实体, §1.2 循环A/B/C)     (窗口结算)      (溢出保护+统计)
        └────────────────────────────┴───────────────────────┴──────────────┘
                                     ▼
                          RenderSurface.submit(SpriteBatch)  ← 渲染帧插值 alpha
```

- **逻辑帧固定 60Hz、渲染帧跟随屏幕**：`tick` 内所有计时（combo 窗口、slash 轨迹、freeze）只吃逻辑 dt，
  与 ProMotion 刷新率解耦；渲染用 `FixedStepDriver.advance` 返回的 alpha 做位置插值。
- 原 `dt==0 → 用上一帧缓存值`（exe `param_1!=0` 分支 / macho `fVar29`）在 `GameWorld` 内保留，
  但**首帧缓存初值 0.0**（[both]，T-006 订正）导致首帧零步进，需在 `start()` 时显式吃掉一帧。

### 5.2 转换管线（构建期一次性，运行期零解析）

1. `.tex` → 解析自定义头 → 中间 PNG（保留 alpha 预乘标记）→ **ASTC 4x4/6x6 (.ktx2)**。
   PVRTC 在 A 系列新 GPU 上已弃用，不做直通。
2. XML 配置 → JSON（`Resources/Content/*.json`）：避开 iOS 27 XML 解析差异，且便于 schema 校验；
   解析器 `FruitListParser` / `WaveParser` 只读 JSON，缺省值以 `WaveInfo` / `FruitInfo` 默认值为准。
3. 字体：原为位图字体图集 → 保留 sprite sheet（保证与原视觉一致），不转 CoreText 字形。
4. 音频：统一转 CAF/m4a 48kHz，播放走 `AVAudioEngine`（原 AudioToolbox/OpenAL 路径仅作音量/时序参考 [待验证]）。
5. 所有产物写 `ContentBundle.manifest.json`（版本 + 哈希），运行时校验缺失即降级到占位资源。

### 5.3 坐标与分辨率基准（Phase 3 核心）

- 原逻辑在**固定归一化坐标**下运行（碰撞半径按 15.0 归一化，`0.5*(d/15)+0.5`）；
  现代设备必须由 `RenderSurface.logicalSize` 反算 `sliceRadiusSquared`，**不可写死像素半径**。
- Safe Area 只影响 HUD/菜单层，**不改变游戏坐标系**（否则切割手感随机型漂移）。
- 120Hz：`CADisplayLink.preferredFrameRateRange` 设 preferred=max；逻辑仍 60Hz，
  渲染做插值 → 高刷屏获得平滑收益但物理一致性不变。
