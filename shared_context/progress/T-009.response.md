## 设计说明

三个文件按“常量、状态、接口”的顺序逐级展开，层次清晰：`Constants.swift` 只收录已闭合且置信度 H/M 的数值，未闭合的数值单列为注释台账，**不写假值**；`GameState.swift` 把 core_logic_notes §0 的 21 个条目对应到 Swift 结构体，保留原始偏移量以方便核对，并把 FUN_00017d74 的 game+0xf0 作为独立补充字段，不混入原表；`REBUILD_BLUEPRINT.md` 覆盖 a–f 六项内容，并把本轮注入缺失的 `slash_geometry.md`、`function_classification.md` 的结论明确改为引用 DECISIONS T-004/T-006/T-007 与 `pending_constants.md`，逐条标注来源标签。

关键取舍：
1. **任务卡与 findings 存在计数冲突**（任务卡写“22 字段表”，core_logic_notes §0 实际为 21 条目），已在蓝图 §2.1 明示，不擅自补充字段。
2. **dt 备用逻辑存在语义矛盾**：两份反编译均显示 `dt != 0` 时取缓存（语义荒谬），而笔记结论为 `dt == 0` 兜底，代码按笔记实现并标 `[待验证]`。
3. 所有**未闭合常量、字段语义、接口参数**（combo 窗口上下限、DAT_004d90b4、Spawner 元素默认偏移、SlashTracker 提交参数、HitTest 第二段截面圆公式）一律做接口参数化或注释占位，**不固定具体值**。

#### 3.1.1 ⚠️ dt 兜底触发条件的语义矛盾（[待验证]，最高优先级的开放项）

两份反编译写的是**同一个**反常形态：

- macho：`fVar29 = PTR[0x44]; fVar10 = param_2; if (param_2 != 0.0) { fVar10 = fVar29; }`
- exe：`if (param_1 != 0.0) { fStack_1c = _DAT_0197f47c; param_1 = _DAT_0197f47c; }`

即字面读作 **「dt ≠ 0 时用缓存替换」**，语义荒谬（正常帧反而用旧 dt）。
而 `core_logic_notes §1.2 步骤 1` 与 `pending_constants C-04` 的文字结论是 **「dt == 0 时用兜底」**。

判定与处理：
- 最可能是 Ghidra 对 `fcmpe` 标志位的反转（两处同一反编译器，同向错误）；
- **本蓝图按「无效 dt → 缓存兜底」实现**（§3.1 的 `effectiveDeltaTime`），
  因为「normal frame 用 stale dt」会导致手感持续落后一帧，与原版可玩性矛盾；
- 该判定**必须**在 Phase 2 用真机 Frida 或第三份证据（ARM 汇编手读 `vcmpe`/`vmrs` 标志序）闭合；
- 闭合前不得把该逻辑写进任何可发货路径的性能关键处（可先在 `GameLoopTests` 里标 TODO）。

            return p2 < entityRadius * entityRadius
        }
