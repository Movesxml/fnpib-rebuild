## 设计说明

T-013 把 `core_logic_notes §2`（连击）与 `§3`（计分/统计）直译为 Swift，严格贴着 `GameWorld.swift` 里已落盘的协议签名实现，不新增协议方法、不引入未落盘类型。

关键取舍：

1. **协议签名不可改** → `ComboTracking.registerSlice` 只拿到 `EntityID`，因此原文 `piVar13[0x21] == 2` 这条实体侧门控无法在 ComboTracker 内判定，明确标注由调用方（GameWorld 步骤 6.4）前置过滤。
2. **ComboEvent 单值返回** → 同帧「计数 + 特殊果」时只回 `.incremented`，`specialBonusApplied` 的 delta 已写入 `state.rhythmFactor`，事件丢失问题写进注释与风险点。
3. **溢出保护** → Swift Int32 溢出会 trap，改用 Int64 累计 + `Int32(truncatingIfNeeded:)` 模拟原 32 位回绕；`mode==4` 不归零、`mode!=5` 超 `0x7fffffff` 归零，逐字对应 §3.2 步骤 4。
4. **窗口上下限** → `DAT_00017024/00017028` 尚未直读，按 T-006「0.1/0.095」口径映射到 `windowBase/windowCap`，改值只需动 Constants。
5. **命中率** → 公式独立为 `AccuracyFormula`（`K=-0.2`、`SCALE=100` 取 Constants），`StatsRecorder.accuracy()` 做便捷封装；`total<=0` 做除零防御（原 C 为浮点除零 UB）。
6. **档位** → 统一 Int64 中间值再 clamp，避免 `combo-3` 在极端值触发 Swift 溢出 trap。

//
//  ComboTracker.swift
//  FNPBCore
//
//  ComboTracking 协议实现（T-013）
//
//  来源：findings/core_logic_notes.md
//    §1.2 步骤 6.4（registerSlice）[both]
//    §1.2 步骤 9   （tickWindow / 结算）[both]
//    §2.2 分支全链（档位 / 事件）[both]
//    数值：Constants.Combo（DECISIONS T-004 M41 双源确认）
//
//  【范围】只做逻辑，不碰 UI；事件经 ComboEvent 交由调用方（GameWorld 步骤 9）分发。
//  【签名边界】ComboTracking 的方法签名由 GameWorld.swift 固定，本文件不得扩展协议。
//

import Foundation

public final class ComboTracker: ComboTracking {

    // MARK: - 注入配置

    /// 首发统计上报通道（GameState.slashesScoringEmitted 语义见 §1.2 步骤 6.4）。
    /// 不进协议签名——ComboTracking 的签名由 GameWorld.swift 固定。
    private let stats: (any StatsRecording)?

    /// 特殊果得分加成量（原 `DAT_004d90b4`，`+0x110 += DAT_004d90b4`）。
    /// ⚠️ [待验证] ARM __stubs 懒绑定桩，静态镜像中不可解（Constants Pending #3）；
    /// 默认 0 = 不改变分值，运行时实测后经初始化注入。
    private let specialFruitBonus: Int32

    /// combo 随机项权重 0.5（公式 `0.5*rand/8+0.75` 内字面量）。[macho H] §1.1
    private static let rhythmRandomWeight: Float = 0.5

    public init(stats: (any StatsRecording)? = nil, specialFruitBonus: Int32 = 0) {
        self.stats = stats
        self.specialFruitBonus = specialFruitBonus
    }

    // MARK: - ComboTracking

    /// §1.2 步骤 6.4：非炸弹命中后的 combo 计数。
    ///
    /// 分支（macho FUN_00016214 顺序）：
    ///  1. 同一实体（+0x180）→ 跳过 combo 计数，**不**覆写实体指针
    ///  2. 否则：+0x174=0；comboArr[+0x8c]=type；+0x90=(type!=0)；首发 slashes/slashesScoring；
    ///     combo++；combo>9 → +0x174=0.095；+0x54 -= combo*(0.5*rand/8+0.75)
    ///  3. 特殊果（+0x1ba）：+0x110 += 加成；+0x54 += -3.0*(0.5*rand/8+0.75) —— 与计数解耦
    ///
    /// ⚠️ 签名限制：原文另有一条门控 `piVar13[0x21] == 2`（实体状态槽=2 → 跳过计数），
    ///    该槽不在 GameState 且本方法只拿到 EntityID，无法在此判定。
    ///    **必须由调用方（GameWorld 步骤 6.4）在调用前过滤**，否则会多计一次 combo。
    public func registerSlice(fruitType: Int32, entity: EntityID,
                              state: inout GameState, rng: any RandomSource) -> ComboEvent? {
        var event: ComboEvent?

        // 1. 同一实体防重复（原 `+0x180 == entity` → 跳窗口检查）
        if state.lastComboEntity != entity {
            state.lastComboEntity = entity
            state.comboWindowTimer = 0                              // +0x174 = 0

            // comboArr[+0x8c] = type（写入位置为当前计数，0 基）
            let slot = Int(state.comboCount)
            if slot >= 0 && slot < state.comboFruitTypes.count {
                state.comboFruitTypes[slot] = fruitType
            } else {
                // 原 C 无边界检查；Swift 越界会 trap → 防御性写末槽
                // [待验证] 理论上 combo ≤ 11（数组容量），此分支不应触发
                if !state.comboFruitTypes.isEmpty {
                    state.comboFruitTypes[state.comboFruitTypes.count - 1] = fruitType
                }
            }

            state.comboTypeFlag = (fruitType != 0) ? 1 : 0           // +0x90 = (type != 0)

            // 首发统计：slashesScoring / slashes；+0x51 = 1
            if !state.slashesScoringEmitted {
                state.slashesScoringEmitted = true
                stats?.add(.slashesScoring, 1)
                stats?.add(.slashes, 1)
            }

            state.comboCount &+= 1                                   // combo++（32 位回绕语义）
            if state.comboCount > Constants.Combo.countThresholdForTightWindow {
                state.comboWindowTimer = Constants.Combo.windowCap   // combo>9 → 0.095
            }

            // +0x54 -= combo * (0.5*rand/8 + 0.75)
            state.rhythmFactor -= Float(state.comboCount) * rhythmTerm(rng)

            event = .incremented(count: state.comboCount,
                                 visualTier: ComboTier.visual(for: state.comboCount),
                                 textTier: ComboTier.text(for: state.comboCount))
        }

        // 2. 特殊果加成（+0x1ba）：与 combo 计数解耦，命中即生效
        if state.specialFruitBonusEnabled {
            let term = rhythmTerm(rng)
            state.lastSliceScore &+= specialFruitBonus                // +0x110 += DAT_004d90b4 [待验证]
            let specialDelta = Constants.Combo.rhythmPenalty * term   // +0x54 += -3.0 * (...)
            state.rhythmFactor += specialDelta
            if event == nil {
                event = .specialBonusApplied(delta: specialDelta)
            }
            // 注：ComboEvent 单值返回，同帧既计数又特殊果时只回 incremented；
            //     specialDelta 已写入 state.rhythmFactor，调用方可按需读取。
        }

        return event
    }

    /// §1.2 步骤 9：combo 窗口推进与到期结算。
    ///
    /// 原文（macho FUN_00016214 步骤 9）：
    ///   若 +0x174 < DAT_00017024 → +0x174 += dt
    ///   若 +0x174 >= DAT_00017028 → 结算（+0x174=0.1、回调链、统计），随后统一清零
    ///   若 +0x174 >= DAT_00017024 → 直接走清零分支
    ///
    /// 重建取值：DAT_00017024 视作 windowBase(0.1) 推进上限，
    ///           DAT_00017028 视作 windowCap(0.095) 结算阈值
    ///           （T-006「combo 窗口 0.1/0.095」+ §7 待读常量按此口径闭合）。
    /// ⚠️ [待验证] 两个数据段常量精确值尚未直读；若后续读到不同值，只需改 Constants。
    public func tickWindow(dt: Float, state: inout GameState) -> [ComboEvent] {
        // 推进：未达上限才累加（原 `+0x174 < DAT_00017024`）
        if state.comboWindowTimer < Constants.Combo.windowBase {
            state.comboWindowTimer += dt
        }

        // 未到期
        guard state.comboWindowTimer >= Constants.Combo.windowCap else { return [] }

        // 到期但无活动 combo：幂等清零（原「直接走清零分支」），不派发事件
        guard state.comboCount > 0 else {
            state.comboWindowTimer = Constants.Combo.windowBase
            state.clearComboTracking()
            return []
        }

        let settledCount = state.comboCount
        let settledTypes = state.comboFruitTypes

        // combo >= 3：统计 combos（原 `"%s_combos"` + `"combos"`）
        // ⚠️ [待验证] 动态键 `"%s_combos"` 的 %s 语义未闭合（FUN_0000342c/000042b4），不臆造；
        //     strawberry_combo_total 需要 fruitType ID 映射，亦未闭合。
        if settledCount >= Constants.Combo.tierEffectStartCount {
            stats?.add(.combos, 1)
        }

        // 结算后：+0x174 = 0.1（作为「已结算」标记，防同帧重复结算）
        state.comboWindowTimer = Constants.Combo.windowBase
        // 统一清零：combo=0; +0x90=0; +0x180=0; +0x178=0; memset(+0x60, 0xff, 0x2c)
        state.clearComboTracking()

        return [.settled(count: settledCount, fruitTypes: settledTypes)]
    }

    /// 复位：清计时器与 combo 状态。原 reset 路径未单独导出 → [M] 语义推断。
    public func reset(state: inout GameState) {
        state.comboWindowTimer = 0
        state.clearComboTracking()
    }

    // MARK: - 内部

    /// 原 `0.5*rand/8 + 0.75`（§1.1 / §1.2 步骤 6.4）。
    /// 每调用一次消耗一次 rng，与原两处 rand 调用对齐（combo 递减 1 次、特殊果 1 次）。
    private func rhythmTerm(_ rng: any RandomSource) -> Float {
        let r = rng.nextFloat()
        return Self.rhythmRandomWeight * r / Constants.Combo.randomDivisor + Constants.Combo.randomBase
    }
}

//
//  ComboTier.swift
//  FNPBCore
//
//  §2「连击族」档位公式（T-013）
//
//  双源确认（DECISIONS T-004 M41 + core_logic_notes §2.3）：
//    visual = clamp(combo - 3, 0, 2)
//    text   = clamp(combo - 2, 1, 5)
//    effect 活跃门限：combo > 2
//
//  【实现说明】combo 为 Int32，直接 `combo - 3` 在极端值下可能触发 Swift 溢出检查，
//  故统一升到 Int64 计算后 clamp 回 Int32。原 C 为 32 位有符号回绕，正常游戏值域内两者一致。
//

import Foundation

public enum ComboTier {

    /// 视觉档位：`clamp(combo - 3, 0, 2)`。§2.2 步骤 4 [both] H
    public static func visual(for comboCount: Int32) -> Int32 {
        clamped(Int64(comboCount) - Int64(Constants.Combo.visualTierOffset),
                min: Int64(Constants.Combo.visualTierMin),
                max: Int64(Constants.Combo.visualTierMax))
    }

    /// 文本档位：`clamp(combo - 2, 1, 5)`。§2.2 步骤 6 [both] H
    public static func text(for comboCount: Int32) -> Int32 {
        clamped(Int64(comboCount) - Int64(Constants.Combo.textTierOffset),
                min: Int64(Constants.Combo.textTierMin),
                max: Int64(Constants.Combo.textTierMax))
    }

    /// 特效 / 音效分支门限：`combo > 2`（§2.2 步骤 1）[both] H
    public static func isEffectActive(for comboCount: Int32) -> Bool {
        comboCount >= Constants.Combo.tierEffectStartCount
    }

    // MARK: - 内部

    private static func clamped(_ value: Int64, min lower: Int64, max upper: Int64) -> Int32 {
        Int32(Swift.min(Swift.max(value, lower), upper))
    }
}

//
//  ScoreSystem.swift
//  FNPBCore
//
//  ScoreDispatching 协议实现（T-013）
//
//  来源：core_logic_notes §3.2（macho FUN_0001cb08 计分事件分发器）[macho H]
//
//  【职责边界】本类不含基础分公式——基础分在命中时写入 GameState.lastSliceScore（+0x110），
//  §3.2 已明确说明；本类只做「事件序号 → 延迟回调出队 → 总分累加 → 溢出保护」。
//

import Foundation

public final class ScoreSystem: ScoreDispatching {

    // MARK: - 延迟回调（UI 滚动计分）

    /// 回调节点：`delay == 0` 立即触发；
    /// 否则在 `mode == 1` 且事件序号超过 delay 后触发（§3.2 步骤 2）。
    public struct DelayedCallback {
        public let delay: Int32
        public let handler: (_ score: Int32, _ comboType: Int32) -> Void

        public init(delay: Int32,
                    handler: @escaping (_ score: Int32, _ comboType: Int32) -> Void) {
            self.delay = delay
            self.handler = handler
        }
    }

    /// 原 `DAT_005576f0` 全局事件序号。
    private var sequence: Int32 = 0

    /// 原 `DAT_005f8dd4` 总分。用 Int64 累计以避开 Swift Int32 溢出 trap，
    /// 对外暴露时按 32 位回绕截断（原 C 的 int 语义）。
    private var accumulated: Int64 = 0

    private var callbacks: [DelayedCallback] = []

    public init() {}

    public var total: Int32 { Int32(truncatingIfNeeded: accumulated) }

    /// 注册延迟回调（原 `DAT_005576e8` 回调链）。
    /// 非协议方法——协议签名由 GameWorld.swift 固定，不得扩展。
    public func schedule(delay: Int32,
                         handler: @escaping (_ score: Int32, _ comboType: Int32) -> Void) {
        callbacks.append(DelayedCallback(delay: delay, handler: handler))
    }

    // MARK: - ScoreDispatching

    @discardableResult
    public func dispatch(score: Int32, comboType: Int32, isScoring: Bool, mode: Int32) -> Int32 {
        // 1. 全局事件序号 +1（原 DAT_005576f0 += 1；&+= 保留 32 位回绕语义）
        sequence &+= 1

        // 2. 遍历回调链：delay==0 立即触发；或 delay < seq 且 mode==1 时出队触发
        //    ⚠️ [M] 推断：触发的节点从队列移除，未触发的保留（原文 FUN_0001d888「清链」语义未完全闭合）
        if !callbacks.isEmpty {
            var pending: [DelayedCallback] = []
            pending.reserveCapacity(callbacks.count)
            for callback in callbacks {
                if callback.delay == 0 || (callback.delay < sequence && mode == 1) {
                    callback.handler(score, comboType)
                } else {
                    pending.append(callback)
                }
            }
            callbacks = pending
        }

        // 3. 总分累加（原 DAT_005f8dd4 += 本次得分）
        //    单次 score 为 Int32，累计 43 亿次才会触及 Int64 上限，实际不可达。
        accumulated += Int64(score)

        // 4. 溢出保护（§3.2 步骤 4）：
        //    mode==4 → 不做归零；否则 total > 0x7fffffff 且 mode!=5 → 归零
        if mode != Constants.Scoring.overflowSkippedMode {
            if accumulated > Int64(Constants.Scoring.intMax)
                && mode != Constants.Scoring.overflowKeepMode {
                accumulated = 0
            }
        }

        // 注：§3.2 步骤 5/6 的 "all" / "upside_down_points" / "score_without_beans" 统计
        //     与成就回调不在本类职责内，由 GameWorld 步骤 10 消费 dispatch 返回值后上报。
        return total
    }

    public func reset() {
        accumulated = 0
        callbacks.removeAll()
        // [M] 推断：新会话从 0 起算；原全局序号是否清零未知
        sequence = 0
    }
}

import Foundation

public final class StatsRecorder: StatsRecording {

    /// 静态键计数（原 FUN_00027588 计数入口）。
    private var counters: [StatsKey: Int32] = [:]

    /// 动态键计数（`"%s_combos"` / `"strawberry_combo_total"` 等，§3.4）。
    private var dynamicCounters: [String: Int32] = [:]

    public init() {}

    // MARK: - StatsRecording

    /// 静态键累加。32 位回绕语义用 `&+`。
    public func add(_ key: StatsKey, _ value: Int32) {
        counters[key, default: 0] = counters[key, default: 0] &+ value
    }

    /// 动态键累加（原字符串哈希通道）。
    public func report(_ dynamicKey: String, _ value: Int32) {
        dynamicCounters[dynamicKey, default: 0] =
            dynamicCounters[dynamicKey, default: 0] &+ value
    }

    // MARK: - 查询（非协议方法）

    public func value(for key: StatsKey) -> Int32 {
        counters[key] ?? 0
    }

    public func value(forDynamicKey key: String) -> Int32 {
        dynamicCounters[key] ?? 0
    }

    public func reset() {
        counters.removeAll()
        dynamicCounters.removeAll()
    }

    // MARK: - 命中率（§3.3）

    /// 以自身 `slashes` / `slashesScoring` / `totalfruit` 计数计算命中率。
    /// - Parameter externalCorrection: 原 `*(param_1 + 0x2c)` 外部修正项 X
    public func accuracy(externalCorrection: Float = 0) -> Int32 {
        AccuracyFormula.rate(totalFruit: value(for: .totalfruit),
                             slashes: value(for: .slashes),
                             slashesScoring: value(for: .slashesScoring),
                             externalCorrection: externalCorrection)
    }
}

// MARK: - 命中率公式

/// §3.3 `FUN_00065ad4` 还原：
/// ```
/// misses = slashes - slashesScoring
/// f      = (total + X + K * misses * total) / total
/// result = f >= 0 ? f * SCALE : 0
/// ```
public enum AccuracyFormula {

    /// 计算命中率整数结果（原 C `(int)` 向零截断）。
    /// - Parameters:
    ///   - totalFruit: 统计键 `totalfruit`
    ///   - slashes: 统计键 `slashes`
    ///   - slashesScoring: 统计键 `slashesScoring`
    ///   - externalCorrection: 原 `*(param_1 + 0x2c)` 外部修正项 X
    public static func rate(totalFruit: Int32,
                            slashes: Int32,
                            slashesScoring: Int32,
                            externalCorrection: Float = 0) -> Int32 {
        // 防御：原实现 total 为 0 时浮点除零；Swift 不允许 NaN → Int32 转换
        guard totalFruit > 0 else { return 0 }

        let misses = Float(slashes &- slashesScoring)           // 32 位回绕语义
        let total = Float(totalFruit)
        let ratio = (total + externalCorrection
                     + Constants.Scoring.hitRateK * misses * total) / total

        let scaled = ratio >= 0 ? ratio * Constants.Scoring.hitRateScale : 0
        guard scaled.isFinite else { return 0 }
        if scaled <= 0 { return 0 }
        if scaled >= Float(Constants.Scoring.intMax) { return Constants.Scoring.intMax }
        return Int32(scaled)                                     // 向零截断，等价 C `(int)`
    }
}

//
//  ComboScoreTests.swift
//  FNPBCoreTests
//
//  T-013 黄金值测试：combo 窗口推进 / 到期结算 / 0.095 封顶 / combo>9 收紧 /
//  双档 clamp 边界 / 溢出保护两模式 / 命中率手算用例
//

import XCTest
@testable import FNPBCore

// MARK: - 测试替身

/// 确定性随机源：按预置序列循环返回浮点值。
private final class FixedRandom: RandomSource {
    private let values: [Float]
    private var cursor: Int = 0

    init(values: [Float] = [0]) {
        self.values = values.isEmpty ? [0] : values
    }

    func nextFloat() -> Float {
        let value = values[cursor % values.count]
        cursor += 1
        return value
    }

    func nextInt(_ upperBound: Int32) -> Int32 { 0 }
    func snapshot() -> UInt64 { UInt64(cursor) }
    func restore(_ s: UInt64) { cursor = Int(s) }
}

// MARK: - 测试

final class ComboScoreTests: XCTestCase {

    private let frame: Float = 1.0 / 60.0

    // MARK: - Combo 窗口推进 / 结算

    func testComboWindowAdvancesAndSettlesAfterCrossingCap() {
        let tracker = ComboTracker()
        let rng = FixedRandom()
        var state = GameState()

        let first = tracker.registerSlice(fruitType: 1, entity: EntityID(rawValue: 1),
                                          state: &state, rng: rng)
        XCTAssertEqual(first, ComboEvent.incremented(count: 1, visualTier: 0, textTier: 1))
        XCTAssertEqual(state.comboWindowTimer, 0)
        // r=0 → term = 0.75 → rhythmFactor = -1 * 0.75
        XCTAssertEqual(state.rhythmFactor, -0.75, accuracy: 1e-6)

        // 5 帧后 timer ≈ 0.0833 < 0.095 → 不结算
        for _ in 0..<5 {
            XCTAssertTrue(tracker.tickWindow(dt: frame, state: &state).isEmpty)
        }

        // 第 6 帧 timer ≈ 0.1 >= 0.095 → 结算
        let events = tracker.tickWindow(dt: frame, state: &state)
        XCTAssertEqual(events.count, 1)
        guard case let .settled(count, fruitTypes) = events[0] else {
            return XCTFail("第 6 帧应派发 settled 事件（timer≈0.1 >= 0.095）")
        }
        XCTAssertEqual(count, 1)
        XCTAssertEqual(fruitTypes, [1] + [Int32](repeating: -1, count: 10))

## 审查风险点（请 Kimi 重点核对）

1. **窗口上下限口径 [待验证]**：`DAT_00017024 / DAT_00017028` 尚未直读，我按 T-006「0.1 / 0.095」把 `windowBase` 当推进上限、`windowCap` 当结算阈值。若后续从数据段读到不同值，需同步改 `tickWindow` 的推进/结算结构（当前是「<0.1 才累加，>=0.095 结算」）。
2. **实体侧门控缺失**：原文 `piVar13[0x21] == 2 → 跳过 combo 计数` 无法由 `registerSlice(EntityID)` 判定，已在注释标红。GameWorld 步骤 6.4 若漏掉这层前置过滤，会多计 combo —— 这是本卡与 T-011 之间的接口约定风险。
3. **特殊果加成值未闭合**：`DAT_004d90b4` 是懒绑定桩，默认注入 0；若运行时实测非 0，需要改初始化参数，不改逻辑。
4. **`ComboEvent` 单值返回的信息损失**：同帧「计数 + 特殊果」只回 `.incremented`，`specialBonusApplied` 事件的 delta 不单独派发（已写入 `state.rhythmFactor`）。若 UI 需要独立触发特殊果动效，需要在 T-014 事件汇聚层补一个组合事件类型，而不是改 `ComboEvent` 枚举。
5. **溢出保护语义映射**：原 C 是 32 位 int 溢出（UB/回绕），我用 Int64 累计 + `truncatingIfNeeded` 表达「> 0x7fffffff」阈值的可判定性。若审查认为原实现实际是 `uint32` 比较，需再核对 `DAT_005f8dd4` 的声明宽度。
6. **`FUN_0001d888`「清链」语义 [M]**：我实现为「触发即出队、未触发保留」，与「整链清空」不同。若是整链清空，延迟回调必须每帧重注册，会影响 UI 滚动计分调用方式。
7. **结算后 timer=0.1 的残余路径**：结算后每帧都会进入「到期但 combo=0 → 幂等清零」分支（无事件、无副作用），行为无害但未必与发售版逐指令一致；`DAT_00017024` 直读后可能需要改成「timer 归 0」。
8. **combo>=3 统计只发静态键 `combos` 1 次**：动态键 `"%s_combos"` 的 `%s` 语义、以及 `strawberry_combo_total` 所需的 fruitType ID → strawberry 映射均未闭合，未臆造。
9. **`ScoreSystem.reset()` 清 `sequence`** 是 [M] 推断（原全局序号生命周期未知）。
10. **本机 Windows 无法 `swift test` 验证**：所有断言均为手算黄金值，编译与浮点边界需 Mac/CI 跑一遍（尤其 `testComboWindowAdvancesAndSettlesAfterCrossingCap` 的 6 帧浮点累加）。
